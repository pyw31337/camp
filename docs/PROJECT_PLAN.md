## 제품 목표

사용자는 지역·차량·캠핑 형태·현장 조건을 넣고, 전국 공영·민간 캠핑장의 **상품 단위** 규격·예약 방법·현장 적합성을 비교한다. 실시간 재고는 전국 커버리지와 계약/API가 모두 갖춰질 때까지 검색·목록에 표시하지 않으며, 상세에서는 공식 사진과 최신 분위기 콘텐츠, 날씨, 이동·통행료, 인근 여행 정보를 서로 다른 근거로 확인한다. 제품 재정의와 단계별 계획은 [서비스 재정의 계획](./SERVICE_REINVENTION_PLAN.md)을 따른다.

## 제품 원칙

1. `캠핑장`과 `판매 상품`을 분리한다. 오토 사이트, 타프존, 쉘터존, 글램핑, 카라반, 캠프닉은 별도 상품이다.
2. 전국 단위 잔여석은 커버리지·갱신·계약 기준을 충족하기 전까지 검색·목록에서 표시하거나 필터링하지 않는다. 접수 기간만 공개한 원천은 `OFFICIAL_APPLICATION_OPEN`으로만 표시하며, 빈자리·매진으로 추정하지 않는다.
3. 수집 시각, 원천 URL, 신뢰도, 만료 시각을 값과 함께 보관한다.
4. 공식 시설 정보, 이용자·소셜 콘텐츠, 추천·검색 결과를 서로 대체하지 않는다.
5. 사진은 사용권이 명시된 공식 자산 또는 플랫폼 임베드로만 노출한다.

- 날짜·인원 조건별로 허용된 원천에서 마지막으로 확인한 빈자리를 `OBSERVED_AVAILABLE`로 보이고, 더 최신의 미관측 결과가 생기면 기본 목록에서 숨긴다. 이는 `LIVE_AVAILABLE`과 다른 관측 기록이며, 관측시각·원문·조건을 반드시 보인다.
- 차별 데이터는 주차 동선, 전력 W, 사이트·구역별 규격·바닥, 불멍 규정, 위생시설 형태/수량, 대여료, 아이 시설·프로그램, 자연·산책 동선이다. 모르는 값은 판단하지 않는다.
- 탐색의 ‘내 캠핑 세팅’은 장비 크기·필요 전력·텐트 옆 주차·장작 불멍을 브라우저의 사용자별 로컬 프로필로 받아 `맞음`·`조건부`·`확인 필요`·`맞지 않음`으로 나눠 카드와 상세에 함께 보인다. 모르는 값은 가능으로 계산하지 않으며, 기본은 모든 후보를 보여 주고 ‘맞지 않는 곳 숨기기’와 ‘등록된 조건만 보기’를 명시적으로 분리한다.
- 첫 구현은 전국의 얕은 추정보다 원천 권한을 확보한 20~30개 파일럿의 깊은 조건표·일별 관측으로 검증한다.

## 현 단계의 우선순위

### Vision 01 승인 전 검증 (2026-10-16)

`/vision/`은 실제 카탈로그를 읽는 독립 디자인 시안이다. 경쟁 예약 채널을 따라 거래 화면을 복제하지 않고, **전국 횡단의 조건 탐색·정규화 스펙·신뢰 경계·이동 맥락**을 의사결정 레이어로 제공하는 방향을 검증한다. A 포스터 리뉴얼은 승인되어 `/explore/`의 실제 UX가 됐고, `/vision/`은 후속 시각 실험만 담당한다.

1. 카드에서 실제 공식 사진을 최대 5장 스와이프하고, 사이트 규격·전기 W·주차·불멍의 **확인된 값만** 짧은 배지로 읽는 방식의 사용성을 검토한다. 값이 없는 곳을 추정하거나 카드에서 실패 배지로 강조하지 않는다.
2. 키워드·테마와 동등한 지도 모드를 확정하고, 핀은 `공식 예약 경로`·`스펙 보유`·`확인 필요`의 의미를 유지한다.
3. `i` 팝오버로 출처·확인 시각을 후순위로 접되, 후기에만 있는 전력/주차/불멍 값은 카드에서 제거하고 상세 기본규격 표의 회색 `확인 필요`로만 남긴다.
4. A 포스터 컴포넌트는 `design/renewal/`을 단일 소스로 삼아 `/explore/`에 발행한다. 다음은 상품·사이트 단위 가격 매핑, 그다음 권한 있는 실시간 재고 피드를 붙인다.

5. Studio 상세은 수집량이 큰 실제 발행 프로필을 표본으로 삼아, `규격·바닥·대여·요금 근거·후기·영상·배치도 원문·주변 생활·로드뷰`가 예약 판단 흐름 안에 함께 놓이는지 검증한다. 이 단계는 정적 시안 검증이며, 개별 예약 URL·가격·실시간 재고는 기존 원천·시각·등급 계약을 충족할 때만 운영 화면에 이식한다.

### 예약 현황을 탐색의 중심으로 (2026-10-14)

날짜 검색의 결과는 예약 방식(온라인/전화)만으로 만들지 않는다. 원천별로 아래 세 상태를 구분한다.

1. `LIVE_AVAILABLE` / `LIVE_SOLD_OUT`: 계약 또는 공식 읽기 API가 **시설·상품·날짜·인원·남은 수량**을 주고, 원천 URL·관측 시각·짧은 만료를 함께 제공할 때만 쓴다.
2. `OFFICIAL_APPLICATION_OPEN`: 공식 원천이 현재 접수 중이며 이용 기간을 주지만 남은 수량은 주지 않는 경우다. 서울 공공서비스예약 Open API를 30분마다 읽어 75분 만료의 읽기 모델로 발행한다. 선택 숙박일 전체가 원천의 이용 기간에 들어갈 때만 후보로 보여 주며, 화면은 ‘공식 접수 중’이라고만 말한다.
3. `OFFICIAL_CHECK_REQUIRED`: 국립공원·숲나들e처럼 공식 잔여 조회 화면은 있으나 자동 읽기 API/계약이 확인되지 않은 경우다. 자동 수집·로그인 우회 없이 사용자가 선택한 날짜를 원문에서 바로 확인하도록 이동시킨다.

전국 단위의 실제 잔여 자리·가격은 1번을 늘리는 것이 다음 우선순위다. 각 예약 제공자의 허용된 API 또는 제휴를 확보하고, 상품 매핑률·날짜/인원 지원·SLA·갱신 실패 시 만료 정책을 검증한 뒤에만 켠다.

1. GitHub Actions 비밀 저장소의 고캠핑 API 키로 `pipeline`의 동기화를 실행하고, 원본 결과를 공개 카탈로그와 PostgreSQL 적재 작업에 순서대로 연결한다. 키는 저장소에 넣지 않는다.
2. `pipeline`의 PostgreSQL 적재를 시설·상품·규격뿐 아니라 공중화장실, 휴게소·졸음쉼터, 주유 가격 관측, 무료 후보, 예약 규칙/계산 일정까지 외부 식별자 기준으로 재실행 가능하게 연결했다. 운영 `DATABASE_URL`을 비밀 관리 환경에 넣으면 동기화 뒤 마이그레이션과 전체 스냅샷 적재가 실행된다. 상세한 원천·주기·롤백 기준은 `docs/DATA_FOUNDATION_PLAN.md`를 따른다.
3. 초기 공식 사진 수집은 고캠핑 `imageList`의 공유 일일 한도 안에서 사진 없는 시설을 먼저 채운다. Pages 용량이 찰 때는 시설당 대표 1장으로 재균형해 전국 커버리지를 완성한 뒤 갤러리를 늘린다. 사진 보강일과 TourAPI 요금·상품 보강일을 분리하고, 이미지 목록을 실제로 재확인한 시설만 삭제 반영한다. 목록·컬렉션·상세의 자체 보관 공식 사진은 480px 축소본을 확대하지 않고 함께 발행한 1280px 대형 파생본을 사용한다. 외부 플랫폼 썸네일은 제공 API·임베드 범위를 넘는 원본 수집·확대로 대체하지 않는다. 사진·상품 가격·예약 가능 상태를 서로 대체하지 않는다.
4. 숲나들e·국립공원·공유누리·지자체·민간 운영자용 예약 제공자 레지스트리를 실제 원천 URL·오픈 규칙·추첨 규칙으로 확대한다.
5. 서울 공식 접수 상태 읽기 모델을 30분마다 갱신하고, 이어서 첫 번째 잔여 수량 읽기 어댑터를 계약 또는 공식 허가 범위에서 구현한다. `LIVE_AVAILABLE`은 날짜·인원별 원천 검증을 거친 값만 반환한다.
6. 파일럿의 자라섬 정적 레코드를 API 응답으로 교체하고, 상품·미디어·공지·예약 제공자 레지스트리를 전국으로 확대한다.
7. 운영자 공식 채널과 허용된 검색/API 연결로 최근 콘텐츠를 상세에 모은다. 항목마다 게시 URL·게시 시각·수집 시각·매칭 점수·표시 권한을 보존하고, 사용자는 정확도순/최신순을 고를 수 있다. 네이버·Meta·TikTok 등은 계약/API/허용 임베드 전까지 원문 검색 링크만 제공하며 결과·이미지·후기를 자동 저장하지 않는다.
8. `pipeline/out/open-calendar.json`을 정적 파일럿 값이 아닌 배포 시 생성되는 읽기 전용 API 응답으로 연결하고, 일정별 공식 원천과 유효 시각을 유지한다.
9. GitHub Pages 데이터 발행기를 통해 예약 캘린더와 권리 검토를 통과한 고캠핑 발견 레코드를 `camping-atlas/public/data/`로 내보낸다. 공공데이터포털의 고캠핑 API 이용허락범위가 제한 없음으로 표기된 원문을 2026-10-13 KST에 확인했고, `GOCAMPING_CATALOG_PUBLISH_APPROVED=true`일 때 시설 식별값·분류·규격·원천만 공개 카탈로그로 발행한다. 일시적 API 실패나 취소된 실행은 직전 검증 공개본을 보존하며, 권리 철회에 따른 비공개만 `ALLOW_GOCAMPING_CATALOG_WITHDRAWAL=true`로 명시한다.
10. 탐색 화면을 검색 목록 하나가 아니라 발견·비교·시설 상세·예약 허브·현장 준비·저장/패스포트의 다페이지 경험으로 확장한다. 상세 예약 CTA는 원천 URL·확인 시각·신뢰도를 갖는 공식 경로만 쓰며, 이미지·후기·영상은 공식 원천 또는 승인된 임베드/링크로만 연결한다. 상세 구현 계획은 [탐색 경험 확장 계획](./EXPERIENCE_EXPANSION_PLAN.md)을 따른다.
11. GitHub Pages 배포 전에는 공개 탐색 데이터가 참조하는 자체 보관 공식 사진의 썸네일·대형 파생본을 전수 대조한다. `media` 브랜치나 파일이 하나라도 누락되면 사진 없는 카탈로그를 배포하지 않고 이전 공개본을 유지한다. iPhone Safari/PWA는 `viewport-fit=cover`와 safe area를 적용해 상태 표시·홈 인디케이터와 고정 조작부가 겹치지 않게 한다.

### 현장 조건 전수 표기 (2026-10-15)

- 고캠핑 기준 3,111곳마다 `field_conditions`를 발행한다. 사이트 규격·바닥재·전기 제공·화로대 배치·장작 판매와 각각의 원천을 한 묶음으로 제공한다.
- 전국 전수 추출의 소개글·시설 분류 신호는 `SURVEYED`로 구분한다. 법정 600W·오토야영장 분류·장작 판매처럼 간접 신호를 실제 최대 W·텐트 옆 주차·장작 허용으로 단정하지 않으며, 내 캠핑 세팅의 고위험 적합 판정은 `VERIFIED` 파일럿 원문에만 쓴다.
- `텐트 옆 주차`, `전력 사용 한도(W)`, `숯 사용 허용`, `장작 사용 허용`, `텐트·타프/쉘터·캐노피 추가 설치 허용/수량`은 고캠핑 표준 원천에 없으므로 `UNKNOWN`/‘확인 필요’로 표기한다. 값이 없다는 이유로 불가·가능을 추정하지 않는다.
- 네이버 예약·캠핏은 고캠핑에 운영자가 등록한 예약 URL을 각각 채널로 분류해 연결한다. 플랫폼 화면의 상품·전력·주차·가격을 자동 수집하거나 저장하지 않으며, 전수 보강은 공식 API·서면 제휴 또는 캠핑장 운영자 인증 입력을 확보한 뒤에만 한다.
- 상세 상단의 `예약 전 중요 정보`는 전력 W 제한·대여 물품/요금·입퇴실·주차·화로 규정처럼 예약 판단에 영향을 주는 공지를 보여 준다. `pipeline/registry/campground-notices.json`에 **원문 URL·확인 시각이 함께 있는 운영자 제공/제휴/API 값**만 넣으며, 공지 원문을 자동 수집·복제하지 않는다. 아직 원문이 연동되지 않은 시설도 그 사실과 예약처 최신 공지 확인 필요를 명확히 표시한다.

### 상세의 판단 카드·콘텐츠 묶음 (2026-10-15)

- 예약 버튼은 해당 업장에 실제 등록된 URL만 쓴다. 전환 우선순위는 **캠핏 → 네이버 예약 → 땡큐캠핑 → 기타 온라인 예약처 → 운영자 홈페이지 → 전화**이며, 화면 CTA는 최우선 경로 **한 개만** 보인다. 낮은 순위 경로는 증빙·갱신을 위해 데이터에만 보존한다. 캠핏·네이버·땡큐캠핑의 일반 목록이나 검색 결과로 임의 전환하지 않으며, 확인·결제·대기 신청은 원 예약처에서 이뤄진다.
- (적용·2026-10-19) 상세 고정 CTA·상세 예약 섹션·비교표의 예약 버튼은 같은 `primaryBooking` 선택기를 사용한다. 네이버 카페·블로그처럼 운영자 페이지일 수 있는 링크는 ‘네이버 예약’ 우선순위로 오인하지 않고 기타 온라인 경로로 다룬다. 전화는 대표 예약 경로가 없을 때의 문의 수단으로만 남긴다.
- 목록 포스터에는 공식 원문 대조를 거친(`VERIFIED`) 사실만 원형 아이콘 배지로 표현한다. 장작 불멍(빨강), 실제 전력 W(주황), 텐트 옆 주차(파랑)를 사용하며, 법정 참고 W·장작 판매·소개글 키워드는 강한 가능 배지로 올리지 않는다.
- 상세는 카카오 지도·길찾기·좌표 기반 로드뷰 바로가기를 제공한다. 주변 화장실·마트·편의점·주유소는 장소별 원문/지도/로드뷰로 연결하며, 제공 권한이 확인된 썸네일이 있을 때에만 사진을 표시한다.
- 블로그·카페·영상은 예약·운영 사실의 근거가 아니다. 수집기는 시설명 매칭, 본문 정보량, 사진 존재, 최신성, 작년 같은 계절성, 중복 여부를 각각 보관해 점수화하고, 정적 공개본에는 원문 링크 또는 허용된 임베드만 보낸다. 네이버 결과의 저장·가공을 금지하는 조건을 우회해 썸네일/본문을 복제하지 않는다.
- 반복 후기 요약은 ‘장점/아쉬운 점’ 모두에 게시 기간·표본 수·근거 링크·마지막 계산 시각을 보여 준다. 표본이 적거나 상충하면 요약을 만들지 않고 ‘후기 더 필요’로 남긴다.

### 비교·콘텐츠·재분석 계약 (2026-10-16)

1. 이 서비스의 첫 역할은 전국 시설과 상품을 같은 항목·단위·표시 순서로 읽게 하는 **비교 카탈로그**다. 시설 카드가 아니라 사이트/상품, 규격, 전기, 주차, 화기, 인원·차량·추가요금, 운영·환불 규칙을 각 값의 원천·확인 시각·등급과 함께 정규화한다.
2. 두 번째 역할은 콘텐츠 허브다. 허용된 API/임베드/외부 링크의 후기·영상·공식 소식을 시설별로 모아 정확도순과 최신순으로 정렬한다. 플랫폼의 약관·저작권을 피해 원문, 이미지, 리뷰를 복제하지 않는다.
3. 세 번째 역할은 키워드·테마·지도·내 위치/행정구역 탐색이다. 네 번째 역할은 이 정규화 스펙을 조건 필터와 2~3곳 비교표에 직접 연결하는 것이다.
4. 무료 운영에서는 GitHub Actions의 일일 기준 데이터·프로필 재생성과 주간 운영자 공식 홈페이지 갱신을 쓴다. 재분석은 새 원천만 대상으로 하고, 후기 장단점·한 줄 요약은 표본 수와 마지막 계산 시각을 함께 남긴다. 실시간 재고·가격은 별도 계약/API 원천이 생기기 전에는 이 재분석 결과로 만들지 않는다.

### 목록 요금 연결 계약 (2026-10-16)

- 상세 프로필의 `PRICE`는 목록용 `pf.p`로 발행한다. 값(`min/max/value`)뿐 아니라 등급, 원문 URL, 원문 게시일, 프로필 산출 시각을 함께 보관하지 못하면 목록에 올리지 않는다.

- 사이트 종류·면수·규격·바닥은 고캠핑 구조화 등록값으로, 상품별 현재 가격은 허용된 TourAPI/운영자/API 연동이 생길 때만 같은 행에 확정 매핑한다. 지금 단계에서 시설 단위 후기 가격을 특정 사이트 구역 가격으로 추정하지 않는다.

- 데이터 운영: 전량 초기 적재와 원천별 주기 갱신의 실행 이력·해시·수신/수용 건수를 조회할 수 있다.

- 가격: 통화, 기준/최대 인원, 추가 인원·차량·옵션, 적용일·요일·시즌·채널을 상품 단위로 저장한다.
- 공간: 사이트 규격은 폭·깊이·면적·바닥·적용 수량·출처를 구분한다.
- 미디어: 모든 카드에 원천과 권리 상태가 있고, 소셜 원문은 임베드·링크 중심으로 표시한다.
- 발행: 공개 정적 카탈로그는 가격·재고·사진 원본을 담지 않고, 기준 시설 식별값·분류·규격·수집 시각·원천만 보존한다.
- 발행 안정성: 새 고캠핑 원천이 없거나 실패한 실행은 마지막 `PUBLISHED` 시설 카탈로그를 빈 목록으로 덮어쓰지 않는다. 원천 보존 허가 철회만 명시적 변수로 비공개 처리한다.
- 지도/날씨: 현재 위치는 사용자의 명시적 동의가 있어야 쓰며, 원좌표를 불필요하게 장기 보관하지 않는다.

- (제안·2026-10-16) **평점 표시**: 네이버·카카오·캠핏·땡큐캠핑 평점은 공개 API가 없고 약관상 자동 수집을 할 수 없어 모으지 않는다. 가능한 길은 ① Google Places API(평점·리뷰 수 제공, 키·과금 필요, 저장 제한이라 화면에서 실시간 호출 + Google 표기 의무), ② 서비스 자체 평가(댓글 giscus 반응 또는 별점) 축적. 그때까지는 카드에 **후기 장단점 한 줄(후기 n건에서 센 주제·건수)**만 보인다(`build-review-digest.mjs`). 소유자 결정: Google 키 발급 여부.
