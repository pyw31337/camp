# 민간 캠핑장 날짜별 빈자리 — 수집 경로 연구 (2026-10-19, Claude)

> 소유자: “국공립보다 민간 캠핑장이 모수도 많고 정보 가치도 크다. 캠핏 제휴는 개인 프로젝트·비사업자라 어렵다.” → 민간 업장의 날짜별 빈자리를 **우리 데이터 수집 원칙(AGENTS.md) 안에서** 얻을 경로를 찾는다.

## 1. 민간 캠핑장은 어디서 예약받나 (카탈로그 2,438곳, 등록 예약 경로 기준)

|---|---|---|

| 자체 홈페이지 | 1,418 | 홈페이지 안 예약 엔진에 따라 다름(아래 2) |

- 홈페이지 링크를 따라가 본 결과(운영자 홈페이지 수집기, 같은 사이트 안만 읽음) 86곳이 외부 예약 엔진으로 이어졌다: `r.camperstory.com` 45, 땡큐캠핑 13, 캠프링크 9, 야놀자펜션 11, 떠나요 6, xticket 2 … 같은 사이트 밖 링크는 따라가지 않으므로 **실제는 더 많다**.
- `r.camperstory.com/?{번호}`는 땡큐캠핑 예약 화면(`m.thankqcamping.com/resv/view.hbb?cseq={번호}`)으로 바로 넘어간다 — 같은 회사 엔진이다.

## 2. 가장 유망: 땡큐캠핑·캠퍼스토리 예약 엔진

- robots.txt: `m.`·`www.`·루트 모두 `User-agent: * / Allow: /`, `Sitemap` 공개 → 자동 접근을 명시적으로 허용.
- 예약 화면은 로그인 없이 열린다(캠핑장 정보·“예약가능 2026.12.31까지”). 날짜별 사이트 상태는 화면 안 요청(`/inc/axCampResVerUrl.hbb`, `/booking/axCampResUrl.hbb`)으로 불러오는 것으로 보이며, **로그인 없이 날짜별 ‘마감/예약가능’이 보이는지는 아직 확인하지 못했다**(1차 렌더링 시험에서 달력 단계까지 가지 못함).
- 다음 단계(스파이크, 반나절):
  1. 업장 1곳에서 날짜 선택 → 사이트 목록까지 사람이 하는 순서를 브라우저로 따라가며, 로그인·캡차·대기열 없이 날짜별 상태가 보이는지 확인.
  2. 보이면: 하루 2~4회, 업장당 다음 2주말만, 호스트 간격 2초↑, 봇 이름 공개로 읽는 수집기(`observe-thankq.mjs`) → `pilot-observations.json`과 같은 관측 계약(관측 시각·원문 URL·근거)으로 저장 → 목록·상세에 “빈자리 n (오전 9시 확인)” 표시. 확정 예약 가능은 아니므로 ‘관측’ 등급과 확인 시각을 붙인다.
  3. 업장 매칭: 카탈로그 예약 경로의 `cseq`/캠퍼스토리 번호 + 홈페이지에서 발견한 엔진 링크(수집기에 ‘외부 예약 엔진 링크 기록’ 추가).
- 이용약관에 자동 수집 금지 조항이 있는지 함께 확인한다(robots 허용과 별개).

## 3. 그 밖의 경로

- **운영자 자체 홈페이지 예약 달력**: 펜션형 예약 솔루션(달력에 ‘예약완료/가능’ 표시)을 쓰는 홈페이지가 있다. 운영자 홈페이지 수집기가 이미 robots를 지키며 읽고 있으므로, 달력 표(날짜·‘완료/가능’)를 알아보는 추출기를 붙이는 방식. 업장마다 형식이 달라 수확률을 표본으로 먼저 잰다.
- **이용자 제보**: 상세의 비회원 댓글처럼 “이번 주말 자리 있음/없음” 제보 버튼(확인 시각·제보자 수 표시, 24시간 뒤 만료).
- **운영자 직접 등록**: 업장이 빈자리를 올리는 간단한 양식(무료 노출). 개인 프로젝트로도 가능하며 정정·삭제 요청 경로와 함께 둔다.
- **하지 않는 것**: 네이버 예약·캠핏·카페 등 robots·로그인·캡차로 막힌 경로의 우회, 앱 내부 API 흉내.
