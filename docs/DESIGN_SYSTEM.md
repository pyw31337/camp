## Vision 01 시각 언어 (제안)

- 팔레트는 먹색 `#0B0E17`, 코럴 `#FF613E`, 라임 `#A8FF3E`, 블루 `#4D6DFF`의 제한된 네 색만 쓴다. 자연 사진을 쓰더라도 UI는 저대비 자연색으로 물들이지 않는다.
- 배경 사진과 정보가 겹치면 사진 자체를 흐리게 저장하지 않고, 컨텐츠 뒤에만 반투명 유리·백드롭 블러를 둔다. 텍스트 대비는 WCAG AA 이상을 유지한다.
- 제목은 아주 큰 굵은 산세리프와 이탤릭 세리프 보조 문구를 대비하고, 레이블·상태는 작고 단단한 모노 타입으로 쓴다.
- 카드 첫 줄은 큰 실제 공식 사진, 다음은 **예약 채널 → 사이트 규격 → 전기/주차/불멍** 순이다. 전기 배지는 `⚡ 600W`, 주차는 `사이트 옆`/`외부 주차`/`차박`, 불멍은 `장작`/`숯만`/`지정 화로대`처럼 값과 범위를 직접 쓴다.
- 값의 근거·확인 시각은 카드 본문을 차지하지 않는다. `i` 버튼 팝오버에 넣되, 후기 언급·추정이면 카드에도 반드시 `확인 필요`를 남긴다.
- 지도는 별도 메뉴이자 키워드·테마와 동등한 탐색 모드다. 핀의 색은 장식이 아니라 검증 예약 경로·규격 보유·확인 필요 상태를 뜻한다.
- 생성 이미지는 일반 브랜드/히어로 분위기에만 쓴다. 특정 캠핑장·상품·시설을 표현하는 사진은 승인된 공식 자산 또는 허용된 링크·임베드만 쓴다.

### Vision 01 압축·탐색 보정 (2026-10-16)

- 첫 화면은 **키워드 · 테마 · 지도** 세 탐색 모드를 동등한 큰 탭으로 보인다. 키워드는 한 줄 입력, 테마는 짧은 칩, 지도는 바로 지도 섹션으로 이동한다. 기능을 설명하는 장문은 넣지 않는다.
- 카드 사진은 고캠핑 상세의 공식 원격 사진만 최대 5장까지 쓴다. 사진 위 `OFFICIAL PHOTO` 같은 배지는 쓰지 않고, 점 표시와 가로 스와이프/드래그만 둔다. 외부 후기·검색 이미지는 카드 레일에 섞지 않는다.
- 카드 배지는 실제 값이 있는 전기 W·장작/숯·주차 방식만 표시한다. 값이 없거나 후기 언급뿐이면 카드에서 생략한다. `확인 필요`는 상세 기본규격 표에서만 회색 본문으로 쓴다.
- 본문은 `word-break: normal`과 자연스러운 줄바꿈을 사용한다. 버튼·탭·칩·수치는 한 줄을 유지하되, 장문을 줄여 해결한다. 강제 `<br>`와 문장형 서비스 설명을 피한다.
- 일반 페이지는 문서만 세로 스크롤한다. 사진·칩 레일은 숨긴 가로 스크롤바와 스와이프/드래그를 쓰며, 페이지 전체의 가로 넘침은 `overflow-x: clip`으로 차단한다.
- 와이드 화면은 동일 폭 카드 4열(1280px 이하 3열), 모바일은 2열로 고정한다. 보조 판단 안내 레일을 제거해 카드 폭이 흔들리지 않게 한다.

### Studio Prototype 01 — 검토용, 운영 화면 미적용 (2026-10-16)

`design/studio-v1/`은 Vision 01의 팔레트와 사용자 첨부 레퍼런스의 정보 밀도를 실제 클릭 가능한
화면으로 검토하는 별도 시안이다. 이 시안은 현재 `/explore/`와 운영 토큰을 바꾸지 않는다.

- **탐색**: 와이드 사진 히어로 안의 `키워드 · 테마 · 지도` 동등 탭, 한 줄 조건 입력, 큰 사진·5장 스와이프·`01~03` 짧은 스펙 행 카드.
- **상세**: 사진 모자이크, 대형 이름, 내 세팅 3칸, 정형 스펙표, 하나의 예약 카드, 후기·영상 프리뷰.
- **지도·비교**: 넓은 지도/결과 분할과 예약·전기·화기·주차·규격의 동일 행 비교.
- **이미지 경계**: `assets/weekend-hero-v1.png`만 디자인 전용 생성 히어로다. 실서비스의 개별 캠핑장·상품 사진은 허용된 공식 자산 또는 플랫폼 임베드만 사용한다.

승인 후에만 실제 데이터 계약과 접근성·반응형 검증을 거쳐 본 시스템에 채택한다.

## v4.2 변경(2026-10-16, 소유자 피드백)

- **히어로는 실제 한국 캠핑장 사진.** 일러스트는 폐기했다(유아 콘텐츠처럼 보임). 생성 사진이 준비될 때까지 고캠핑 공식 사진(일곱식구 캠핑장, 전북 정읍, 해 질 녘 불 켜진 텐트)을 `build-hero.mjs`로 레이아웃별로 잘라 쓴다. 출처는 히어로 오른쪽 위 (i)에만.
- **글자 자리 딤 ≥ 80%.** 글자가 지나가는 영역(PC 왼쪽 약 40%, 모바일 위 약 36%)은 바탕색 85~94%로 덮는다. 사진의 주인공(텐트)은 그 밖에 둔다.
- **배지 색 복원.** 전기 = 라임 `#C8FF00`(잉크 글자), 불멍 = 주황 `#FF4A1C`(흰 굵은 글자). 소유자가 좋다고 확인한 조합.
- **버튼·칩은 1~2단어, 한 줄.** `white-space: nowrap`, 좌우 여백 16px 이상, 칩 줄은 줄바꿈 대신 가로 스크롤, 건수는 가는 회색. 예: ‘온라인 예약 채널’→‘온라인 예약’, ‘공식 홈페이지로 예약하기’→‘홈페이지 예약’, ‘공식 접수 검색’→‘검색’.
- **가로폭 전체.** 헤더·본문·보조 페이지의 최대 폭(1240/1280px)을 없애고 좌우 여백 `clamp(16px, 3vw, 48px)`만 둔다. 히어로·상세 사진은 가장자리까지(라운드 없음).
- 모바일의 떠 있는 ‘지도 보기’ 버튼은 칩을 가려 목록에서는 숨기고, 지도 화면에서만 ‘목록 보기’로 보인다.

## v4.1 “Ink & Leaf” (2026-10-16, 소유자 피드백 반영)

시안 캔버스(Claude Design, 비공개)에서 A~D 네 콘셉트를 비교한 뒤 소유자가 고른 조합이다.

| 가져온 것 | 출처 콘셉트 | 화면에서 |
| --- | --- | --- |
| 같은 항목·같은 순서의 스펙 표, 촘촘한 정보 | C 스펙북 | 상세 ‘이용 정보’, 비교표 |
| 넓은 사진을 배경처럼 | B 숲속 유리 | 탐색·홈 히어로, 상세 사진 묶음 |
| 굵기 대비(900 ↔ 200–300) | A 필드 저널 | 히어로 제목, 캠핑장 이름(첫 단어 900·나머지 200), 숫자 |
| 지도로 찾기 | D 아침 지도 | 메뉴 ‘지도’(`explore/?view=map`), 찾는 방법 탭(키워드·테마·지도) |

### 1. 원칙

1. **밝은 화면만.** 어두운 면(밤 숲 예약 카드·밤 유리 탭 바·어두운 히어로 그라데이션)을 쓰지 않는다.
2. **글자는 잉크/흰 강약, 액센트는 초록 하나.** 버튼·선택·예약·시간 신호가 초록이다. 파랑은 쓰지 않는다.
3. **경계는 선 대신 면과 그림자.** 카드·섹션·칩·입력은 테두리 없이 연한 회녹색 면(`--mc-soft`)이나 그림자(`--mc-shadow-1/2`). 조작 요소는 알약형.
4. **사진과 페이지의 경계는 흰 그라데이션.** 흐림·유리 패널은 쓰지 않는다. 글이 올라가는 쪽(PC 왼쪽, 모바일 위쪽)을 바탕색으로 서서히 덮고, 맨 아래는 바탕색으로 녹인다.
5. ~~히어로는 만든 그림~~ → v4.2에서 실제 한국 캠핑장 사진으로 바꿈(위 v4.2 참고). 레이아웃마다 주인공 위치가 달라 `hero-campsite`(탐색 PC)·`hero-campsite-m`·`hero-home`·`hero-home-m`을 따로 굽는다.
6. **출처·설명은 (i) 말풍선에만.** 데이터 기준일·사진 출처·판정 기준·원문 문장은 화면에 늘어놓지 않고 (i)를 눌렀을 때만 보인다(`tipBtn`, 홈 `InfoTip`). 화면에는 값만 크게.
7. **추측은 ‘확인필요’.** 원천이 없는 칸은 반드시 ‘확인필요’ 배지. 채운 배지는 출처 있는 값만.

### 2. 토큰 (`--mc-*`)

| 토큰 | 값 | 쓰임 |
| --- | --- | --- |
| canvas / paper / soft / soft-2 | `#F5F6F4` / `#FFFFFF` / `#EEF1ED` / `#E4E8E3` | 바탕 / 카드 / 칩·입력·보조 면 |
| ink / ink-2 / ink-3 | `#101414` / `#4B5350` / `#69716D` | 글자 3단계(본문 대비 4.5:1 이상) |
| accent / accent-ink / accent-tint | `#00875A` / `#0A6E45` / `#E4F4EA` | 주 버튼·선택(흰 글자 4.55:1) / 초록 글자 / 예약 카드·칩 면 |
| volt(전기) / flame(불멍) | `#C8FF00`(잉크 글자) / `#FF4A1C`(흰 굵은 글자) | 포스터 배지(v4.2 복원) |
| shadow-1 / shadow-2 / shadow-float | 4·16px 6% / 8·28px 12% / 2·10px 14% | 카드 / 떠 있는 패널 / 지도 버튼·핀 |
| radius | 12 / 16 / 22 / 28 · 알약 999 | |

### 3. 포스터 배지(카드 사진 위, 상세 제목 아래, 지도 미리보기)

순서 고정: **전기 → 불멍 → 주차·차박** 3칸 + 왼쪽 위 **시간 신호** 1칸.

| 칸 | 채운 배지(출처 있음) | 확인필요 |
| --- | --- | --- |
| 전기 | 라임 `⚡600W` `⚡1.1kW` (원문 대조·운영자 공개 W) | `전기 W 확인필요`(고캠핑에 전기 제공만 있음) |
| 불멍 | 불꽃 `장작 OK` `숯만`, 흰 바탕 불꽃 글자 `화로대 개별`(고캠핑 등록, 연료 미확인), 흰 `화기 불가`/`개인 화기 불가` | `불멍 확인필요` |
| 주차·차박 | 잉크 `차박 OK` `사이트 옆 주차`, 흰 `외부 주차` `짐수레 이동` | `주차 확인필요` |
| 시간 | 초록 `오픈 D-2 · 10:00`, `공식 접수 중`, `빈자리 …` | 없으면 칸을 비움 |

근거 등급과 원문 문장은 상세 제목 옆 (i)에 모인다(`badgeTip`). 운영자 공개 값(OPERATOR)은 배지로 보이지만 내 세팅 ‘맞음/맞지 않음’ 판정에는 쓰지 않는다(`docs/OPERATOR_SITE_FACTS.md` 4절).

### 4. 카드

- 테두리 없는 그림자 카드, 사진 4:3, 이름 900, 지역·사이트 수 300, 내 세팅 판정·요금대.
- **후기 장단점 한 줄**: 👍(초록) 장점 주제 2개, 👎(불꽃) 단점 주제 2개, 각 건수와 `후기 n건`. 이 캠핑장 글로 확인된 후기 요약에서 센 것이며 협찬 편향을 말풍선으로 밝힌다. 언급이 없으면 ‘언급 없음’.
- 홈 테마 줄의 썸네일도 같은 배지(채운 것만)와 장단점 한 줄을 쓴다(`featured.json`의 `bd`·`rv`).

### 5. 지도(Uber Base 패턴 참고)

Uber Base는 흑백 바탕 + 한 가지 액센트, 테두리 없는 그림자 카드, 알약 버튼·칩, 떠 있는 흰 원형 컨트롤이 특징이다. 이를 따라:
- 핀은 값 하나를 담은 **검정 알약 + 꼬리**(전력 W·불멍·주차 순으로 아는 값, 모르면 흰 알약에 이름). 고른 핀은 초록.
- 핀을 누르면 상세로 바로 가지 않고 **아래 미리보기 카드**(사진·이름·지역·배지·‘자세히’)가 올라온다. PC는 왼쪽 아래 420px 카드.
- 묶음(클러스터)은 잉크 원. 지도 모드에서는 히어로를 숨기고 PC는 왼쪽 목록 패널 + 넓은 지도.

### 6. 하단 탭(모바일)

홈 · 찾기 · 지도 · 예약 일정 · 내 캠핑. **면(채운) 아이콘 24px + 글자 12.5px**, 선택은 초록 글자·연초록 알약. 테마는 찾기 화면의 ‘테마’ 탭과 PC 메뉴로 들어간다(탭은 다섯 칸을 넘기지 않는다).

### 7. 검증(2026-10-16)

Playwright 1440·390px로 홈·탐색 목록·상세·출처 말풍선·지도 모드를 확인했다. 가로 스크롤 0, 페이지 오류 0. 로컬에는 공식 사진 묶음(`media/`)이 없어 카드 사진은 테마 사진으로 대신 띄워 확인했다. 카카오 지도는 로컬 도메인이 등록되지 않아 핀·미리보기 카드는 배포 주소에서 확인해야 한다.

| 앱 구조 | Airbnb 지도→일정 전환, Resy 지도 검색, Travel Explorer, Luxury/NomadStay | 하단 탭(떠 있는 알약형 포함), 지도 위 칩·바텀시트, 사진이 위·본문이 아래인 세로 카드, 큰 모서리(16~32) |

**취향·지향점 해석**: “감성 사진 앱”이 아니라 **자연을 배경으로 한 차분한 도구**다. 사진이 분위기를 만들고, 그 위의 유리 패널이 판단에 필요한 사실만 짧게 말한다. 색은 탁하고 따뜻하며, 화려한 초록·파랑보다 이끼·모래·밤 숲. 글자는 크고 단단하게, 조작은 알약형으로 손에 잡히게. 앱처럼 하단 탭과 시트로 움직이되 PC에서는 넓은 화면을 정보로 채운다.

## 조사에서 채택한 원칙

여행 예약 화면은 영감용 사진보다 먼저 **여행 조건과 확정 가능성**을 이해시켜야 한다. 에어비앤비의 사례는 하나의 핵심 흐름, 읽기 쉬운 문장 중심 정보 계층, 저장·예약 같은 명확한 행동을 강조한다. Booking.com의 개발 문서는 위치·날짜·인원과 필터를 분리해 실시간 재고·가격을 조회하는 검색 구조를 보여 준다. Google의 반응형 가이드는 화면 폭이 바뀔 때 단순 축소 대신 탐색·필터 컨테이너의 형태를 바꾸도록 권한다.

캠핑 AR·예약 UI 레퍼런스는 몰입감 있는 실제 사진, 부드러운 큰 모서리, 작은 정보 배지, 사진과 일정의 분리된 계층을 보여 준다. 클로드 시안 v2는 그중에서도 **예약 오픈을 첫 번째 콘텐츠로 두고, 검색을 한 장의 큰 히어로 카드 안에 넣으며, 모바일에서 가로 카드와 하단 탐색을 쓰는 구조**가 서비스 목적에 잘 맞았다. 현재 공개 화면은 이 시안의 메뉴 순서, 큰 사진 히어로, 우측 통계 배지, 히어로 안의 탭형 검색, 가로 예약 카드, 사진 카드, 모바일 하단 탐색을 기준 레이아웃으로 구현한다. 시안의 콘셉트 이미지와 예시 캠핑장·가격은 사용하지 않는다. 대신 공식 사진의 원문, 확인일, 예약의 확정 경계를 같은 화면에서 보여 준다.

그래서 모여라 캠핑은 다음 순서를 고정한다.

1. 첫 화면에서 `캠핑장/예약 오픈`을 고르고 지역·날짜·인원을 입력한다.
2. 검색 바로 다음에 검증 상태와 확인일이 있는 예약 오픈 카드를 둔다.
3. 실제 캠핑장 카드는 사진·형태·규격·정원·공식 예약 안내만 짧게 보여 준다.
4. 상세에서 상품별 재고·요금·정책을 보여 주고, 날씨·경로·주변 여행은 보조 판단 정보로 분리한다.
5. 사진·가격·재고가 없는 기준 시설 레코드는 사진 카드로 꾸미지 않고, 데이터 수집 현황과 검증 상태에서만 보여 준다.

참고: [Airbnb UX 사례](https://design.google/library/airbnb-invites-you-in), [Booking.com 검색 사용 사례](https://developers.booking.com/demand/docs/accommodations/search-examples), [Google의 반응형 패턴 가이드](https://design.google/library/introducing-resizer), [Camping AR App](https://dribbble.com/shots/11607072-Camping-AR-App), [Camping App Exploration](https://dribbble.com/shots/27205497-Camping-App-Exploration), [Camping App Design](https://dribbble.com/shots/10165691-Camping-App-Design), [Ski camps booking](https://dribbble.com/shots/22874895-Snowboard-Ski-camps-booking-web-app), [Camping reservation UI](https://dribbble.com/shots/7140824-Camping-reservation-ui).

- 760px 이하: 메뉴 숨김 → 하단 탭 5개(홈·찾기·테마·예약오픈·관심).

## 캠핑장 상세 템플릿 v2 (2026-10-14)

- 순서: 사진 모자이크(넓으면 큰 1장+4장, 좁으면 넘기는 슬라이드, ‘사진 N장 모두 보기’) → 제목·한 줄·위치·테마 칩 → 한눈에 타일(사이트 면수·반려견·화장실/샤워·예약 방식·후기·영상, 모바일은 가로 스크롤) → 행동 4개(길찾기·전화·관심·공유) → 목차(예약·사이트·요금·후기·시설·주변·정보·댓글) → 섹션 카드.
- 섹션마다 다른 시각 요소: 예약=짙은 초록 카드(D-day 배지·큰 버튼, 경로·규칙은 접기), 이런 곳이에요=아이콘 격자, 사이트=형태별 타일(면수 비율 막대)·크기/바닥 칩(바닥 색 점), 후기 요금=범위 막대+시기별 타일, 상품=사진 카드 레일, 후기=영상 레일·쇼츠 레일(분리)·방문자 사진 격자(+N)·글 카드(썸네일·출처 배지·‘정보 많음’)와 정렬 탭, 시설=큰 숫자 타일·가능/불가 배지, 정보=아이콘 목록.
- 간격: 8의 배수. 섹션 카드 안쪽 여백 `--pad`(24px, 640px 이하 16px), 섹션 사이 16px(모바일 12px), 섹션 안 묶음 사이 16px, 묶음 안 12px. 가로 레일은 `margin: 0 calc(-1 * var(--pad))` + 같은 안쪽 여백으로 첫 항목이 제목 선에 맞는다(이전 영상 레일 왼쪽 어긋남 수정).
- 출처·확인 시각·주의 문구(`.trust`)는 본문에 쓰지 않는다. 화면을 그린 뒤 `tipify()`가 가까운 제목 옆 (i) 버튼으로 옮기고, 누르면 말풍선으로 보인다.
- 사진은 모두 라이트박스: 좌우 버튼·키보드(←/→/Esc)·스와이프/드래그(50px 이상), 바깥 누르면 닫힘. 검색 썸네일(작은 사진)은 확대하지 않고 ‘원문에서 크게 보기’ 링크를 둔다.

## 세로 스크롤 소유권 (2026-10-14)

- 일반 화면은 문서(`html`/`body`)만 세로 스크롤한다.
- 탐색 상세는 열리는 순간 문서 루트를 잠그고, `.sheet-panel` 하나만 세로 스크롤한다. 따라서 배경 목록과 상세 내용이 동시에 움직이거나, 두 개의 세로 스크롤바가 나타나지 않는다.
- 수평 칩·사진 레일은 좁은 화면에서의 의도된 가로 탐색이며, 세로 스크롤바를 추가하지 않는다. 새 `overflow-y` 컨테이너는 모달·상세처럼 불가피한 경우에만 만들고, 그때는 배경 문서 잠금까지 같은 변경에서 검증한다.

## 이미지 원칙

- 실제 캠핑장 카드: 운영자·공식·계약된 공급자 이미지와 권리·확인일을 함께 표시한다.
- GitHub Pages 파일럿: 운영자 공식 홈페이지가 제공하는 실제 시설 사진을 외부 원문으로 표시하고, 카드마다 원문 링크·운영자·확인일을 표시한다. 원본 파일은 저장하지 않는다.
- 이미지 카드: 16:9 비율, `object-fit: cover`, 고정된 정원·가격 정보와 시각적으로 분리된 메타데이터를 쓴다.
- 접근성: 대표 이미지는 대체텍스트를 제공하고, 장식용 카드는 빈 대체텍스트를 사용한다.
- 현재 화면: 히어로와 상품 카드에는 자라섬캠핑장 운영기관의 시설 안내 원문 이미지만 사용한다. 소셜·후기 사진은 카드 썸네일로 쓰지 않는다. 예외(2026-10-14 소유자 요청): 공식 사진이 없는 캠핑장의 탐색 목록 썸네일에만 관련도 검사를 통과한 Daum 검색 썸네일 URL을 ‘검색 사진’ 표기와 함께 쓴다(저장·확대 없음).
