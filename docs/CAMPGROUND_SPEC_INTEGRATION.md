# 캠핑장 스펙 통합 — “캠핑장의 다나와”를 만드는 데이터·화면 설계

> 작성 2026-10-15 KST (Claude) · 상태: 1단계 구현(스펙 시트·비교표), 2~4단계 계획<br>
> 관련: `SERVICE_REINVENTION_PLAN.md` 9장, `PILOT_INTAKE_CONTRACT.md`, `SOCIAL_SEARCH.md`, `DESIGN_SYSTEM.md` v3

## 1. 문제와 우리 자리

캠핏·땡큐캠핑·네이버 예약 등 어느 플랫폼도 “최고”가 아니다. 각자 입점 업장의 **예약**은 잘 하지만, 업장마다 중요한 정보는 이렇게 흩어져 있다.

- 운영자 공지·상품 설명 속 긴 문장: 입·퇴실, 얼리/레이트, 매너타임, 2박 우선, 인원·차량·방문객 추가 요금, 반려견 조건, 대여 품목·가격, 행사·할인
- 공공 원천: 고캠핑 시설·규격·바닥, 공공예약 접수 상태, 인허가
- 이용자 글: 블로그·카페·영상(최신 분위기, 실제 경험)

모여라캠핑은 **실시간 예약을 대체하지 않는다.** 대신 “모르는 캠핑장을 찾고, 그 캠핑장에 대해 지금 인터넷에 있는 모든 것을 한 번에 보는 곳”이 된다. 핵심은 흩어진 문장을 **같은 사전·같은 순서의 스펙**으로 바꿔 나란히 비교하게 하는 것이다(다나와·에누리의 스펙표처럼).

## 4. 근거 등급과 신뢰 규칙

| 등급 | 원천 | 화면 | 쓰임 |
| --- | --- | --- | --- |
| `OPERATOR` 운영자 확인 | 운영자 제출 조건표·공지(원문 URL·확인일 필수) | 굵은 값 + 진한 칩 | 스펙 확정값, 필터·내 세팅 판정 |
| `OFFICIAL_TEXT` 공식 소개 | 고캠핑 운영자 소개글 등 공식 등록 문장 | 굵은 값 + 연한 칩 | 스펙 값(원문 문장 함께) |
| `MENTION` 후기 언급 | 블로그·카페 요약 | “후기 언급 13:00 (2건)” | **단서**. 확정 칸에 올리지 않음, 질문 생성·검수 우선순위 |

- 모든 값에 원문 문장(quote)·출처·날짜. 원문 없는 값은 만들지 않는다.
- 후기 귀속: 캠핑장 이름 핵심어가 제목·요약에 있어야 하고, “N곳·추천·모음·TOP”이나 📍·번호 목록이 여럿인 **묶음 글은 제외**(2026-10-15 실행에서 2,463건 제외).
- 후기 값이 갈리면 “후기마다 다름” 경고 → 사장님께 물어볼 질문으로 이어진다.
- 행사 언급은 최근 60일 글만, 기간이 지나면 자동 숨김. 기간 없는 ‘할인’ 문구는 행사로 올리지 않는다.
- 이 규칙은 `SOCIAL_SEARCH.md`의 “검색 결과를 가격·운영 사실의 근거로 쓰지 않는다”와 같다: 후기 언급은 사실 칸이 아니라 단서 칸에만 간다.

## 5. 화면 구성

1. **상세 ‘이용 정보 스펙’** (중요 정보 바로 아래, 목차 ‘이용 정보’): 6개 묶음 카드 × 고정 필드. 칸마다 확정값/확인 필요 + 후기 언급(건수·충돌) + “원문 문장 N” 펼치기. 상단에 `확인 N/14` 점수 — 정보가 많은 곳을 한눈에.
2. **비교표**: 같은 14개 필드를 2~3곳 나란히(다나와식). 공유 링크 `#cmp=`.
3. **사장님께 물어볼 것**: 입·퇴실이 확인 안 됐거나 후기마다 다르면, 1박 일정인데 연박 규칙을 모르면 질문을 자동으로 넣는다.
4. **정보 고치기·운영자 조건표**: 같은 섹션 아래 링크. 제보는 검수 뒤 `OPERATOR`로 승격.

다음(2·3단계): 목록 카드에 “스펙 확인 N/14” 배지, 필터(얼리 체크인 가능·1박 가능·방문객 허용·대여 있음), “최근 30일 인터넷” 타임라인(블로그·카페·영상·공지 변경을 시간순으로), 공지 변경 이력(이전 값→새 값, 날짜).
