**취향·지향점 해석**: “감성 사진 앱”이 아니라 **자연을 배경으로 한 차분한 도구**다. 사진이 분위기를 만들고, 그 위의 유리 패널이 판단에 필요한 사실만 짧게 말한다. 색은 탁하고 따뜻하며, 화려한 초록·파랑보다 이끼·모래·밤 숲. 글자는 크고 단단하게, 조작은 알약형으로 손에 잡히게. 앱처럼 하단 탭과 시트로 움직이되 PC에서는 넓은 화면을 정보로 채운다.

### 2. 콘셉트: 숲의 밤, 캔버스 텐트

- **분위기**: 해 질 녘 캠프 사이트. 캔버스(텐트 천) 바탕 + 이끼 + 밤 숲의 깊은 대비 + 모닥불 불씨 한 점.
- **역할 분리**: 이끼(moss)=행동·확인됨, 불씨(ember)=곧 열림·주의·소개글 기반, 밤(night/solid)=선택·주 버튼, 세이지=다크 모드의 주 버튼·탭 선택.
- **신뢰 표현**: 근거 등급 칩(원문 대조=solid, 고캠핑 등록값=moss tint, 소개글 기반=ember tint, 확인 필요=회색)이 브랜드 색 체계 안에 들어 있다.

### 4. 사이트맵 v3 (주소는 그대로, 이름·묶음만 바꿈)

```text
홈(/camp/)                    오늘 열리는 예약·추천·검색 시작
├─ 캠핑장 찾기(/explore/)       목록+지도, 필터·내 캠핑 세팅·공식 접수 날짜 검색
│   └─ 캠핑장 상세(#c=id)       사진 → 제목 카드 → 중요 정보 → 예약 → 내 세팅 → 확인·준비 → 사이트·조건 → 후기 → 시설·주변 → 정보
│   └─ 조건 비교(#cmp=a,b,c)    2~3곳 근거 등급 포함 비교, 링크 공유
├─ 테마(/explore/themes/)      장면으로 고르기 → 찾기의 같은 조건으로
├─ 예약 일정(/explore/openings/) 캠핑장별 예약 오픈 일정(이전 ‘예약오픈’)
└─ 내 캠핑(/explore/passport/)  내 캠핑 세팅 요약 · 비교함 · 관심 · 최근 본(이전 ‘관심’)

```

모바일 하단 탭: **홈 · 찾기 · 테마 · 예약 일정 · 내 캠핑** (떠 있는 밤색 유리 알약, 선택은 세이지). PC 상단: 같은 메뉴를 외곽선 알약으로, 현재 메뉴는 solid.

### 5. 레이아웃·구성

- **카드**: 사진(16:10)이 위, 사진 위에 근거 배지(유리 알약, 최대 3), 아래 본문(이름·지역·내 세팅 판정·근거 태그·예약·요금). 목록은 `auto-fill minmax(17.5rem, 1fr)`라 PC는 2열 이상, 모바일은 1열이며 같은 내용.
- **상세**: 사진 모자이크/슬라이드 → 사진 아래쪽을 덮는 제목 카드(시트 느낌) → 섹션 카드(28px). 예약 카드는 밤 면. 하단 예약 바는 알약 버튼.
- **앱 셸**: 모바일은 떠 있는 탭 바(하단 8px 띄움, 시트·지도·비교 바가 그 위에 맞춰 올라감), PC는 유리 상단 바.

## 조사에서 채택한 원칙

여행 예약 화면은 영감용 사진보다 먼저 **여행 조건과 확정 가능성**을 이해시켜야 한다. 에어비앤비의 사례는 하나의 핵심 흐름, 읽기 쉬운 문장 중심 정보 계층, 저장·예약 같은 명확한 행동을 강조한다. Booking.com의 개발 문서는 위치·날짜·인원과 필터를 분리해 실시간 재고·가격을 조회하는 검색 구조를 보여 준다. Google의 반응형 가이드는 화면 폭이 바뀔 때 단순 축소 대신 탐색·필터 컨테이너의 형태를 바꾸도록 권한다.

캠핑 AR·예약 UI 레퍼런스는 몰입감 있는 실제 사진, 부드러운 큰 모서리, 작은 정보 배지, 사진과 일정의 분리된 계층을 보여 준다. 클로드 시안 v2는 그중에서도 **예약 오픈을 첫 번째 콘텐츠로 두고, 검색을 한 장의 큰 히어로 카드 안에 넣으며, 모바일에서 가로 카드와 하단 탐색을 쓰는 구조**가 서비스 목적에 잘 맞았다. 현재 공개 화면은 이 시안의 메뉴 순서, 큰 사진 히어로, 우측 통계 배지, 히어로 안의 탭형 검색, 가로 예약 카드, 사진 카드, 모바일 하단 탐색을 기준 레이아웃으로 구현한다. 시안의 콘셉트 이미지와 예시 캠핑장·가격은 사용하지 않는다. 대신 공식 사진의 원문, 확인일, 예약의 확정 경계를 같은 화면에서 보여 준다.

그래서 모여라 캠핑은 다음 순서를 고정한다.

1. 첫 화면에서 `캠핑장/예약 오픈`을 고르고 지역·날짜·인원을 입력한다.
2. 검색 바로 다음에 검증 상태와 확인일이 있는 예약 오픈 카드를 둔다.
3. 실제 캠핑장 카드는 사진·형태·규격·정원·공식 예약 안내만 짧게 보여 준다.
4. 상세에서 상품별 재고·요금·정책을 보여 주고, 날씨·경로·주변 여행은 보조 판단 정보로 분리한다.
5. 사진·가격·재고가 없는 기준 시설 레코드는 사진 카드로 꾸미지 않고, 데이터 수집 현황과 검증 상태에서만 보여 준다.

참고: [Airbnb UX 사례](https://design.google/library/airbnb-invites-you-in), [Booking.com 검색 사용 사례](https://developers.booking.com/demand/docs/accommodations/search-examples), [Google의 반응형 패턴 가이드](https://design.google/library/introducing-resizer), [Camping AR App](https://dribbble.com/shots/11607072-Camping-AR-App), [Camping App Exploration](https://dribbble.com/shots/27205497-Camping-App-Exploration), [Camping App Design](https://dribbble.com/shots/10165691-Camping-App-Design), [Ski camps booking](https://dribbble.com/shots/22874895-Snowboard-Ski-camps-booking-web-app), [Camping reservation UI](https://dribbble.com/shots/7140824-Camping-reservation-ui).

## 디자인 시안 v2 (2026-10-12, 이전 기준 — v3로 대체)

핵심 기능 선정과 무학습 원칙은 [CORE_FEATURES_UX.md](./CORE_FEATURES_UX.md), 레퍼런스 분석은 같은 문서 4장을 따른다.

### 소스와 빌드
- 원본: `design/mockup-v2/src.html` (아이콘은 `#l-이름`=Lucide, `#t-이름`=Tabler outline으로 참조)
- 빌드: `cd design && npm install && npm run build` → `mockup-v2/index.html`에 쓰인 아이콘만 SVG 스프라이트로, 쓰인 글자만 Pretendard 서브셋(woff2 base64)으로 인라인. 서브셋에는 `pip install fonttools brotli` 필요.
- 앱 이식 시: `pretendard` npm 패키지(또는 동적 서브셋 CSS)와 `lucide-react`, `@tabler/icons-react`를 쓴다.

### 색 (4계열만)

| 토큰 | 라이트 | 다크 | 의미·용도 |

| `--green` | `#1F9D5C` | `#3DBB78` | 브랜드·주 행동·선택·적합 표시(레퍼런스 ‘Camping App Exploration’의 숲 초록) |

| 중립 | `#17211C` 글자 / `#57635C` 보조 / `#F4F5F2` 바탕 / `#FFFFFF` 면 / `#E1E6E0` 선 | 대응 다크값 | 나머지 전부 |

상태(선착순·추첨·재오픈·상시)는 색 대신 아이콘+단어로 구분한다: 번개(`l-zap`), 티켓(`t-ticket`), 되돌리기(`l-rotate-ccw`).

### 타이포
Pretendard Variable 한 가지. 제목 800, 본문 400~600, 숫자 `tabular-nums`, 자간 -0.01~-0.045em.

### 형태
- 반경: 10 / 16 / 24 / 32px. 히어로·갤러리 32, 카드 24, 칸 16.
- 그림자 2단계만(`--shadow-1` 카드, `--shadow-2` 떠 있는 요소: 검색 카드, 예약 카드, 시트).
- 사진 위 정보는 유리 칩(반투명 + blur)으로. 카드 사진 모서리의 하트는 ‘노치’ 처리.

### 줄바꿈 규칙 (v2.1, 소유자 요구)
- 라벨·버튼·칩·탭·카드 제목·수치는 **어떤 폭에서도 줄바꿈하지 않는다**. 공간이 부족하면 (1) 짧은 문구로 바꾸고(`<span class="l">캠핑장 찾기</span><span class="s">캠핑장</span>`), (2) 배치를 바꾼다(그리드 전환, 아이콘만 표시). 말줄임(…)은 마지막 안전장치이며 검사에서 0건이어야 한다.
- 줄바꿈 허용은 문장 단락뿐이며 `data-wrap-ok`로 표시한다.
- 캐러셀 카드는 항상 화면 안에 한 장이 통째로 들어온다: PC 4열·3열·2열은 정확히 나눠 떨어지게, 모바일은 `100% - 28px`(다음 카드가 살짝 보임). PC에는 좌우 버튼.
- 검사: 시안 변경 시 `cd design && npm run build && bash checks/run.sh`로 320~1920px 16개 폭의 줄바꿈·말줄임을 확인한다(결과 0건이어야 함).

### 무료 캠프 사이트 카드
조건 3칸(무료·취사·화장실)을 아이콘 타일로 보여 주고, 확인된 칸만 초록. 확인 중은 물음표 아이콘과 회색. ‘실제 공고’/‘예시’ 태그로 출처 성격을 구분한다.

## 캠핑장 상세 템플릿 v2 (2026-10-14)

- 순서: 사진 모자이크(넓으면 큰 1장+4장, 좁으면 넘기는 슬라이드, ‘사진 N장 모두 보기’) → 제목·한 줄·위치·테마 칩 → 한눈에 타일(사이트 면수·반려견·화장실/샤워·예약 방식·후기·영상, 모바일은 가로 스크롤) → 행동 4개(길찾기·전화·관심·공유) → 목차(예약·사이트·요금·후기·시설·주변·정보·댓글) → 섹션 카드.
- 섹션마다 다른 시각 요소: 예약=짙은 초록 카드(D-day 배지·큰 버튼, 경로·규칙은 접기), 이런 곳이에요=아이콘 격자, 사이트=형태별 타일(면수 비율 막대)·크기/바닥 칩(바닥 색 점), 후기 요금=범위 막대+시기별 타일, 상품=사진 카드 레일, 후기=영상 레일·쇼츠 레일(분리)·방문자 사진 격자(+N)·글 카드(썸네일·출처 배지·‘정보 많음’)와 정렬 탭, 시설=큰 숫자 타일·가능/불가 배지, 정보=아이콘 목록.
- 간격: 8의 배수. 섹션 카드 안쪽 여백 `--pad`(24px, 640px 이하 16px), 섹션 사이 16px(모바일 12px), 섹션 안 묶음 사이 16px, 묶음 안 12px. 가로 레일은 `margin: 0 calc(-1 * var(--pad))` + 같은 안쪽 여백으로 첫 항목이 제목 선에 맞는다(이전 영상 레일 왼쪽 어긋남 수정).
- 출처·확인 시각·주의 문구(`.trust`)는 본문에 쓰지 않는다. 화면을 그린 뒤 `tipify()`가 가까운 제목 옆 (i) 버튼으로 옮기고, 누르면 말풍선으로 보인다.
- 사진은 모두 라이트박스: 좌우 버튼·키보드(←/→/Esc)·스와이프/드래그(50px 이상), 바깥 누르면 닫힘. 검색 썸네일(작은 사진)은 확대하지 않고 ‘원문에서 크게 보기’ 링크를 둔다.

## 세로 스크롤 소유권 (2026-10-14)

- 일반 화면은 문서(`html`/`body`)만 세로 스크롤한다.
- 탐색 상세는 열리는 순간 문서 루트를 잠그고, `.sheet-panel` 하나만 세로 스크롤한다. 따라서 배경 목록과 상세 내용이 동시에 움직이거나, 두 개의 세로 스크롤바가 나타나지 않는다.
- 수평 칩·사진 레일은 좁은 화면에서의 의도된 가로 탐색이며, 세로 스크롤바를 추가하지 않는다. 새 `overflow-y` 컨테이너는 모달·상세처럼 불가피한 경우에만 만들고, 그때는 배경 문서 잠금까지 같은 변경에서 검증한다.

## 이미지 원칙

- 실제 캠핑장 카드: 운영자·공식·계약된 공급자 이미지와 권리·확인일을 함께 표시한다.
- GitHub Pages 파일럿: 운영자 공식 홈페이지가 제공하는 실제 시설 사진을 외부 원문으로 표시하고, 카드마다 원문 링크·운영자·확인일을 표시한다. 원본 파일은 저장하지 않는다.
- 이미지 카드: 16:9 비율, `object-fit: cover`, 고정된 정원·가격 정보와 시각적으로 분리된 메타데이터를 쓴다.
- 접근성: 대표 이미지는 대체텍스트를 제공하고, 장식용 카드는 빈 대체텍스트를 사용한다.
- 현재 화면: 히어로와 상품 카드에는 자라섬캠핑장 운영기관의 시설 안내 원문 이미지만 사용한다. 소셜·후기 사진은 카드 썸네일로 쓰지 않는다. 예외(2026-10-14 소유자 요청): 공식 사진이 없는 캠핑장의 탐색 목록 썸네일에만 관련도 검사를 통과한 Daum 검색 썸네일 URL을 ‘검색 사진’ 표기와 함께 쓴다(저장·확대 없음).
