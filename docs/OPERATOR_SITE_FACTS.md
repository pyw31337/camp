# 운영자 홈페이지 사실 수집 (2026-10-16)

> 소유자 요구: “확인필요가 많으면 신뢰가 떨어지고 다른 플랫폼을 또 찾아가야 한다. 실제 업장 정보를 최대한 모아 확인된 정보로 보여 달라.”<br>
> 이 문서는 **어디까지 자동으로 모으고, 어디부터는 모으지 않는지**와 그 결과가 화면에서 어떤 등급으로 보이는지 정한다.

## 1. 원천 범위

| 원천 | 수집 | 이유 |
| --- | --- | --- |
| 한국관광공사 고캠핑 API | 이미 사용(기준 모수) | 공공데이터 이용 허락. 전기 제공·화로대(개별/불가)·사이트 규격·바닥 등 구조화 값 |
| **운영자 자체 홈페이지** | **이번에 추가** | 운영자가 스스로 공개한 이용 안내. robots.txt를 지키고 문장만 짧게 인용 |
| 운영자 공지(제출·확인) | 기존 `registry/campground-notices.json` | 운영자 확인 등급(OPERATOR) |
| Daum 검색 후기 요약 | 기존 `sync-social` | 후기 ‘언급’으로만 사용(확정 칸에 올리지 않음) |
| 네이버 예약·플레이스, 캠핏, 땡큐캠핑, 야놀자·여기어때, 인스타그램, 블로그·카페 본문 | **자동 수집 안 함** | 각 서비스 이용약관이 자동 수집·재게시를 금지한다. 제휴·공식 API가 생기면 별도 원천 승인 카드(`PILOT_INTAKE_CONTRACT.md`)로 연다 |
| Google Places 등 해외 지도 API | 보류 | 키·과금이 필요하고, 약관상 장기 저장이 제한된다(place_id 외 캐시 기한). 소유자 결정 대기 |
| 숲나들e·국립공원 등 공공 예약처 | 링크만 | 예약 상태는 공식 API가 있을 때만(`availability` 읽기 모델) |

`lib/operator-site.mjs`의 `PLATFORM_HOSTS`에 걸리는 도메인은 홈페이지로 등록돼 있어도 읽지 않는다. 시·군 통합 예약 사이트처럼 **여러 캠핑장이 같은 홈페이지를 쓰면** 문장이 어느 시설 것인지 알 수 없으므로 배지 사실과 스펙 시트에 쓰지 않는다.

## 2. 흐름

```text
camping-atlas/public/explore/data/campgrounds.json (homepage)
  └─ scripts/crawl-operator-sites.mjs       주 1회(operator-sites.yml) · robots 준수 · 호스트별 1초 · 사이트당 ≤6쪽
       └─ registry/operator-site-snippets.json  문장(≤140자)·쪽 URL·확인 시각만. 전문 저장 금지
            ├─ scripts/build-operator-facts.mjs  → campgrounds.json의 of = { w, pk, fire, cc }  (data-sync)
            ├─ scripts/build-spec-sheet.mjs      → camps/{id}.json의 spec (입·퇴실·매너타임·인원 추가·반려동물 …)
            └─ scripts/build-house-rules.mjs     → camps/{id}.json의 house_rules(금지·이용 제한·이용 수칙·운영 안내·공지) + campgrounds.json의 nr(불가 태그)
```

- `of.w` 전력 W(여러 값이면 낮은 값 + `max`), `of.pk` 주차(`SITE_SIDE`/`EXTERNAL`), `of.fire` 불멍(`FIREWOOD_OK`/`CHARCOAL_ONLY`/`NO_FIRE`), `of.cc` 차박(true/false).
- 2026-10-19: 금지·제한·수칙·운영 문장도 남기고(이용 규칙), 공지 게시판 글은 `notices: [{ title, url(글 주소), date }]`로 따로 저장한다(`noticeLinks`). 이용약관·개인정보 문구는 규칙으로 쓰지 않는다.
- 값마다 `q`(원문 문장)·`u`(그 문장이 있던 쪽 URL)·`t`(확인 시각). 120일 넘은 확인값은 쓰지 않는다.
- 문장끼리 어긋나면(예: 사이트 옆 주차 + 외부 주차) 값을 만들지 않고 ‘확인필요’로 남긴다.

## 3. 추출 규칙(보수적)

- 질문형(FAQ 제목, “가능한가요?”)은 버린다.
- 부분 규칙(텐트 안·데크 위·강풍 시·특정 기간·“C타입만”·“~에서만”)은 시설 전체 값이 아니므로 버린다.
- “숯 추가 1만원”처럼 요금 문장은 불멍 규칙으로 읽지 않는다. “불가능”을 “가능”으로 읽지 않는다.
- 전력은 300~3,000W만 받는다. 발전·충전 문장은 뺀다.
- “차량진입금지”처럼 맥락 없는 짧은 문장은 어느 구역 얘기인지 몰라 받지 않는다.
- 회귀 테스트: `pipeline/test/operator-site.test.mjs`(실제 오탐 문장으로 작성).

| UNKNOWN | 원천 없음 | 점선 ‘확인필요’ | 확인 필요 |
