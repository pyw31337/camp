# 민간 캠핑장 날짜별 빈자리 — 수집 경로 연구 (2026-10-19, Claude)

> **소유자 결정(2026-10-19 저녁)**: 빈자리는 전국 3,000여 곳 전부에 줄 수 없으면 일부만 보여 주는 것은 의미가 없다 → **빈자리 표시는 하지 않는다.** `THANKQ_VACANCY_PUBLISH`는 켜지 않고, 화면의 빈자리 칸(`vacancy.json`이 있을 때만 보임)은 잠든 채 둔다. 이용자 ‘자리 있음/없음’ 제보·운영자 홈페이지 예약 달력 추출도 같은 이유로 진행하지 않는다. 땡큐캠핑 수집은 **사이트 사실(규격·바닥·요금·입퇴실)** 용도로만 계속한다.

> 소유자: “국공립보다 민간 캠핑장이 모수도 많고 정보 가치도 크다. 캠핏 제휴는 개인 프로젝트·비사업자라 어렵다.” → 민간 업장의 날짜별 빈자리를 **우리 데이터 수집 원칙(AGENTS.md) 안에서** 얻을 경로를 찾는다.

## 1. 민간 캠핑장은 어디서 예약받나 (카탈로그 2,438곳, 등록 예약 경로 기준)

| 자체 홈페이지 | 1,418 | 홈페이지 안 예약 엔진에 따라 다름(아래 2) |
| 네이버 예약 | 394 (booking.naver.com 69 + 지도·플레이스 링크) | **불가** — robots.txt `User-agent: * Disallow: /` |

- 홈페이지 링크를 따라가 본 결과(운영자 홈페이지 수집기, 같은 사이트 안만 읽음) 86곳이 외부 예약 엔진으로 이어졌다: `r.camperstory.com` 45, 땡큐캠핑 13, 캠프링크 9, 야놀자펜션 11, 떠나요 6, xticket 2 … 같은 사이트 밖 링크는 따라가지 않으므로 **실제는 더 많다**.
- `r.camperstory.com/?{번호}`는 땡큐캠핑 예약 화면(`m.thankqcamping.com/resv/view.hbb?cseq={번호}`)으로 바로 넘어간다 — 같은 회사 엔진이다.

## 2. 가장 유망: 땡큐캠핑·캠퍼스토리 예약 엔진

- robots.txt: `m.`·`www.`·루트 모두 `User-agent: * / Allow: /`, `Sitemap` 공개 → 자동 접근을 명시적으로 허용.
- 예약 화면은 로그인 없이 열린다(캠핑장 정보·“예약가능 2026.12.31까지”). 날짜별 사이트 상태는 화면 안 요청(`/inc/axCampResVerUrl.hbb`, `/booking/axCampResUrl.hbb`)으로 불러오는 것으로 보이며, **로그인 없이 날짜별 ‘마감/예약가능’이 보이는지는 아직 확인하지 못했다**(1차 렌더링 시험에서 달력 단계까지 가지 못함).
- 다음 단계(스파이크, 반나절):
  1. 업장 1곳에서 날짜 선택 → 사이트 목록까지 사람이 하는 순서를 브라우저로 따라가며, 로그인·캡차·대기열 없이 날짜별 상태가 보이는지 확인.
  2. 보이면: 하루 2~4회, 업장당 다음 2주말만, 호스트 간격 2초↑, 봇 이름 공개로 읽는 수집기(`observe-thankq.mjs`) → `pilot-observations.json`과 같은 관측 계약(관측 시각·원문 URL·근거)으로 저장 → 목록·상세에 “빈자리 n (오전 9시 확인)” 표시. 확정 예약 가능은 아니므로 ‘관측’ 등급과 확인 시각을 붙인다.
  3. 업장 매칭: 카탈로그 예약 경로의 `cseq`/캠퍼스토리 번호 + 홈페이지에서 발견한 엔진 링크(수집기에 ‘외부 예약 엔진 링크 기록’ 추가).
- 이용약관에 자동 수집 금지 조항이 있는지 함께 확인한다(robots 허용과 별개).

## 2-1. 스파이크 결과 (2026-10-19, Claude) — 로그인 없이 날짜별 사이트 상태가 보인다

- 캠핑장 화면(`/resv/view.hbb?cseq=N`)이 날짜를 고르면 부르는 `POST /resv/axResCampSite.hbb`(`campseq, res_dt, res_edt, res_days, site_tp`)가 **로그인·캡차·대기열 없이** 사이트별 카드를 돌려준다. 로그인은 사이트를 눌러 결제로 넘어갈 때만 요구된다(`goNoMemResAlert`).
- 카드마다: 사이트 이름, **상태(`예약가능`·`예약완료`·`예약불가`)**, 입·퇴실 시각, **규격(가로×세로 m)**, **1박 요금(날짜별)**, 바닥, 주차(텐트 옆/주차장), 기준 인원, 반려동물·차박 가능 표시.
  - 예: 2026-10-24(토) 12개 사이트 전부 예약완료 / 2026-10-21(수) 10개 예약가능 — 같은 사이트가 평일 8만·토요일 9만원.
- 업장 찾기: 공개 자동완성 `POST /resv/ax_camp_name.hbb`(`ser_camp_name`) → `[{campSeq, campName, campType, shortAddress}]`. 이름(꼬리말 제외)과 **시·군·구가 같은 한 곳**만 맞춘다(`lib/thankq.mjs pickMatch`). 표본 40곳 중 1곳만 맞음 — 대부분의 민간 업장은 땡큐캠핑을 쓰지 않는다(맞지 않은 곳은 결과 자체가 없음). 링크로 이미 알려진 곳 35곳.
- **이용약관**(2025-08-21 시행, 서비스 이용약관 회원의 의무): “서비스에서 얻은 정보를 복제, 출판 또는 제3자에게 제공하는 행위” 금지. 회원 계약 조항이라 비회원 자동 조회에 바로 적용되진 않지만, 날짜별 상태를 대량으로 다시 게시하는 것은 데이터베이스 제작자 권리 문제가 될 수 있다.

### 원천 승인 카드 — `thankq` (docs/PILOT_INTAKE_CONTRACT.md 2절)

| 항목 | 내용 |
|---|---|
| 원천 ID | `thankq` (땡큐캠핑·캠퍼스토리 엔진, `m.thankqcamping.com`) |
| 방식 | 공개 예약 화면(로그인 전) — robots.txt `User-agent: * / Allow: /`, 사이트맵 공개 |
| 허용 범위 | **사이트 사실**(업장이 등록한 규격·바닥·요금·입퇴실·주차·반려동물·타입) → `APPROVED_FACTS_ONLY` (AGENTS.md 데이터 수집 원칙: 플랫폼에 실린 업장 사실). **사이트 상태(빈자리)** → `PENDING`: 공개 표시는 소유자 결정 후 |
| 빈자리 권한 | 관측(특정 시각의 화면 상태)만. 결제 확정 아님. 수량은 사이트 수 기준 |
| 요청 정책 | 봇 이름 공개 UA, 호스트 간격 2초↑, 실행당 상한(기본 2,500), 하루 2회(06·18시 KST), 연속 실패 5회면 중단 |
| 근거 | robots.txt, 이용약관(위), 캠핑장 화면이 부르는 공개 응답 |
| 갱신·철회 | 매칭 실패는 30일 뒤 재확인. 업장·플랫폼이 요청하면 `THANKQ_ENABLED=off`로 즉시 중단·삭제 |

### 구현 (2026-10-19)

- `pipeline/lib/thankq.mjs`(파서·매칭·날짜), `pipeline/scripts/collect-thankq.mjs`(매칭 → 다음 토요일 2주 사이트 목록), `pipeline/scripts/build-thankq-facts.mjs`(탐색 데이터 반영), `.github/workflows/thankq.yml`(하루 2회 + 증분 발행), 테스트 `pipeline/test/thankq.test.mjs`.
- 저장: `pipeline/registry/thankq.json` — `matches{id: {cseq, via: link|name}}`, `sites{id: {cseq, checked_at, date, url, sites[]}}`(상태 제외 사실만).
- 화면: 상세 ‘사이트 규격 및 1박 요금’ 표가 예약 화면 사이트를 우선 사용(같은 조건 사이트는 한 줄, 근거 (i)·날짜별 예약 화면 링크), 프로필 입·퇴실·1박 요금(OPERATOR, 다른 근거 없을 때), 목록 ‘사이트 최대 W×Dm · 예약 화면 N개 사이트’, 조건 검색 사이트 크기, 대표 예약 경로(등록 경로가 없을 때 땡큐캠핑 화면).
- 사실 원장: 원천 `booking_engine`(PRICE_NIGHT·SITE_SIZE·SITE_SURFACE·CHECKIN_TIME·CHECKOUT_TIME).
- **빈자리**: 같은 응답의 상태는 `pipeline/out/thankq-vacancy.json`에만 남는다. 저장소 변수 `THANKQ_VACANCY_PUBLISH=on`이면 `explore/data/vacancy.json`(만료 14시간)을 발행하고, 화면은 이미 준비돼 있다 — 목록 날짜 판단 `빈자리 n/전체`·`만석(관측)`(빼지 않고 뒤로), 상세 ‘주말 빈자리 관측’(확인 시각·예약처 링크).

## 3. 그 밖의 경로

- **운영자 자체 홈페이지 예약 달력**: 펜션형 예약 솔루션(달력에 ‘예약완료/가능’ 표시)을 쓰는 홈페이지가 있다. 운영자 홈페이지 수집기가 이미 robots를 지키며 읽고 있으므로, 달력 표(날짜·‘완료/가능’)를 알아보는 추출기를 붙이는 방식. 업장마다 형식이 달라 수확률을 표본으로 먼저 잰다.
- **이용자 제보**: 상세의 비회원 댓글처럼 “이번 주말 자리 있음/없음” 제보 버튼(확인 시각·제보자 수 표시, 24시간 뒤 만료).
- **운영자 직접 등록**: 업장이 빈자리를 올리는 간단한 양식(무료 노출). 개인 프로젝트로도 가능하며 정정·삭제 요청 경로와 함께 둔다.
- **하지 않는 것**: 네이버 예약·캠핏·카페 등 robots·로그인·캡차로 막힌 경로의 우회, 앱 내부 API 흉내.
