# 전국 캠핑 데이터 기반 계획

> 최종 갱신: 2026-10-14 KST
> 상태: PostgreSQL 스키마·멱등 적재기·임시 DB 검증 워크플로 구현 완료. 운영 DB 연결 대기.

## 목표와 표시 원칙

모여라 캠핑은 전국 시설을 먼저 넓게 수집하고, 변동성이 큰 값만 원천별 주기로 갱신한다. 값마다 원천 URL, 관측 시각, 신뢰 등급, 만료 또는 검토 상태를 남긴다. 다음 표시는 절대 섞지 않는다.

- **시설/규격**: 고캠핑 등 등록 원천의 정적 사실. 상품별 가격·정원·재고로 추정하지 않는다.
- **예약 오픈 일정**: 제공자 공통 규칙으로 계산한 일정. 시설별 잔여 수량이 아니다.
- **실시간 예약 가능**: 계약 또는 공식 읽기 API가 정확한 시설·상품·날짜·인원 조건과 짧은 만료 시간을 제공할 때만 `LIVE_AVAILABLE` 또는 `LIVE_SOLD_OUT`으로 기록한다. 그 전에는 `OFFICIAL_CHECK_REQUIRED`와 공식 이동 링크를 쓴다.
- **공식 접수 상태**: 원천이 접수 기간·이용 기간·‘접수중’을 제공하되 잔여 수량을 주지 않는 경우 `OFFICIAL_APPLICATION_OPEN`으로 별도 발행한다. 이는 빈자리·매진·결제 가능을 뜻하지 않으며 `availability_snapshot`의 재고 값으로 적재하지 않는다.
- **무료 캠핑**: 이용료·취사 허용·화장실을 별개 사실로 검증한다. 세 가지가 모두 유효한 공식 근거를 갖기 전에는 후보/확인 필요로만 노출한다.

## 수집·활용 매트릭스

| 범주 | 초기 적재와 원천 | DB 모델 | 갱신 목표 | 사용자 활용 |
| --- | --- | --- | --- | --- |
| 등록 야영장·기본 스펙 | 한국관광공사 고캠핑 API 전체 | `campground`, `product`, `inventory_unit`, `source_assertion` | 일 1회 + 증분 | 전국 발견, 캠핑 형태·면수·규격·공식 링크 |
| 예약 정책·오픈 일정 | 숲나들e·국립공원·서울 예약 공식 URL을 사람이 검토한 레지스트리, 이후 공식 API | `provider_policy_template`, `booking_rule_event` | 일 1회 계산, 원문 변경 시 즉시 | “예약 오픈 예정”, 추첨/선착순 구분 |
| 공식 접수 상태(재고 아님) | 서울시 공공서비스예약 Open API의 상태·접수/이용 기간 | 짧은 TTL 공개 읽기 모델(향후 `source_assertion` 실행 이력) | 30분, 75분 만료 | 선택 숙박일을 덮는 ‘공식 접수 중’ 후보와 원문 링크. 잔여 수·매진 표시는 금지 |
| 실제 재고·가격 | 공급자 계약/공식 읽기 API만 | `reservation_channel_product`, `availability_snapshot`, `rate_plan` | 원천 SLA·짧은 TTL | 조건별 실시간 가능/매진. 현재는 적재 금지 |
| 공중화장실 | 행안부 전용 파일/API 우선, OSM은 보조·출처 표시 | `public_toilet`, `campground_nearby_toilet` | 일 1회 원천 수집, 지오코딩 보강 시 재연결 | 캠핑장 주변 300m/2km 안내와 접근성 필터 |
| 휴게소·졸음쉼터·주유가 | 한국도로공사 API, 전국 졸음쉼터 표준데이터, OSM 보조 | `road_stop`, `road_stop_fuel_observation` | 시설 주 1회 이상, 주유 가격은 공식 API 허용 범위에서 일 1회 | 출발/도착 경로 위 쉼터·편의시설·가격 시점 안내 |
| 무료 캠프 | 공공시설 개방정보로 후보 발견 + 운영기관 원문으로 확정 | `campground_candidate`, `free_camp_assessment` | 공공시설 분기 확인, 후보는 원문 확인 때 갱신 | 무료/취사/화장실 상태를 각각 공개 |

경로 선은 요청 시 지도/경로 엔진으로 계산하고 사용자의 출발지·경로 이력은 장기 저장하지 않는다. DB에는 재사용 가능한 정적 시설 좌표와 캠핑장 근방 연결만 저장한다.

## 초기 대량 적재 순서

1. PostgreSQL 16+에 `db/001`~`db/007`을 적용한다. 마이그레이션은 파일 해시와 세션 잠금을 사용하고, 각 파일의 스키마 변경과 적용 이력을 하나의 트랜잭션으로 기록한다.
2. 고캠핑 전체 스냅샷을 외부 식별자 기준으로 적재한다. 2026-10-13 기준 GitHub 동기화 결과는 3,118곳이며, 가격·재고는 포함하지 않는다.
3. 행안부 공중화장실 전용 파일을 전량 적재하고 좌표 보강 후 캠핑장과 연결한다. 로컬 확인에서 원본 53,584행을 수신했다. 현재 원천은 WGS84를 항상 주지 않으므로 지오코딩 방법·정밀도도 저장한다. 최초 전량 보강은 수동 실행에서 `geocode_max_calls=30000`처럼 명시하고, 정기 실행은 캐시를 재사용하며 2,000건씩 진행한다.
4. 한국도로공사 키가 있으면 공식 휴게소·편의시설·주유 가격을, 없으면 졸음쉼터와 OSM 보조 데이터를 적재한다. OSM은 귀속 문구와 ODbL 검토 상태를 함께 보관한다.
5. 무료 후보와 예약 규칙을 별도 검토 큐로 적재한다. 후보가 곧 무료 확정 데이터가 되지 않는다.
6. 서울 공공예약의 공식 접수 상태를 전국 탐색 데이터와 매칭해 공개 읽기 모델로 발행한다. `source_url`, `dataset_url`, `observed_at`, `expires_at`, 원천 등급, 매칭 신뢰도를 함께 보관하며, 원천이 제공하지 않는 `remaining_count`는 `null`로 유지한다. 스키마 변경·DB 마이그레이션은 하지 않는다.

## 운영 주기와 실패 처리

- 30분: 서울 공공예약 공식 접수 상태. 실행 지연·원천 실패 시 기존 공개본을 보존할 수 있으나, 브라우저와 소비자는 `expires_at` 이후 상태를 즉시 무시한다.
- 일별: 고캠핑, 예약 오픈 캘린더, 공중화장실 원천, 계약된 예약 재고/가격, 공식 주유 가격. 공중화장실 주소 지오코딩은 기본 2,000건 배치로 캐시를 이어서 채우며, 대량 최초 적재만 수동 입력값으로 확대한다.
- 주별: 졸음쉼터·휴게소 시설 재검증, OSM 보조 데이터 및 공간 연결 재계산.
- 분기별: 공공시설 개방정보 전체 재수집과 무료 후보 재검토. 데이터셋의 전국 병합 시차도 수집 실행 이력에 남긴다.
- 수시: 운영기관 공지, 폐장·휴장, 시설별 예약 규칙 변경, 원천 오류/정책 변경.

각 실행은 `ingestion_run`에 수신/수용/제외 건수, 페이로드 해시, 원천 URL, 관측 시각, 실패 요약을 남긴다. 부분 수집·좌표 미확보·만료 사실은 성공처럼 덮어쓰지 않는다. OSM/Overpass가 실패하면 최근 성공 캐시를 사용하되 `stale` 상태와 수집 시각을 표시한다.

## 마이그레이션·롤백 전략

`db/005`~`db/007`은 기존 행을 삭제하거나 타입을 바꾸지 않는 추가형 마이그레이션이다. 롤백은 새 뷰·인덱스·테이블·타입을 의존성 역순으로 제거하고, 운영 데이터가 있는 경우 먼저 백업/이관 여부를 결정한다. 이미 적용된 파일은 수정하지 않고 다음 번호의 보정 마이그레이션을 추가한다. CI는 매 PR에서 빈 PostgreSQL 16 컨테이너에 전체 적용, 컨텍스트 중복 적재, 재적용을 검증한다.

## 운영 시작에 필요한 결정

1. PostgreSQL 제공자(권장: 관리형 PostgreSQL 16+와 백업/PITR)와 `DATABASE_URL` 비밀값, TLS 정책을 정한다.
2. 공중화장실 지오코딩의 카카오 키 사용 한도와 보관 기간을 확정한다.
3. 한국도로공사 `EX_API_KEY`, 예약 제공자별 계약/API 접근 범위, 재배포 조건을 확인한다.
4. 실제 예약 현황은 공급자별 시설·상품 매핑과 SLA가 검증된 뒤에만 단계적으로 켠다.
