- **주변시설 실제 모습 = 로드뷰**: 각 줄 오른쪽 `로드뷰` 버튼 → 화면 안 팝업(카카오 지도 JS SDK 로드뷰, 120m 안 가장 가까운 사진, 없으면 안내). 키·SDK가 없으면 카카오맵 로드뷰 새 창. 줄 자체는 지도. PC 3열(카드 최소 340px)로 이름이 잘리지 않게.
- **검색 사진은 쓰지 않는다(2026-10-19 첫 실행 표본)**: 블로그 대표 썸네일 24장 중 실제 가게 모습 5장(안내문·배너·관계없는 풍경 다수). 엉뚱한 사진보다 아이콘 + 로드뷰. 사진 칸(64px)·출처 표기 코드는 관광공사 사진에 쓰고, 검색 사진은 `NEARBY_SEARCH_PHOTOS=on`일 때만 붙는다.

## 전 화면 스크린샷 점검 v2 (2026-10-19 저녁, Claude · 소유자 요청)

PC 1440 · 태블릿 1024/768 · 모바일 390으로 홈·목록·지도·상세(정보 많은/공공/적은 곳)·비교·테마와 날씨 팝업을 찍어 고쳤다.

- **상세 레이아웃(소유자)**: 오른쪽 세로 예약 칸(`.d-side`, sticky)을 없애고 **제목 오른쪽**으로 올렸다(`.d-head` 2열: 이름·소개·배지 | 예약 카드). 태블릿 이하는 제목 아래 한 줄, 모바일은 하단 예약 막대 + 접수·오픈 정보가 있을 때만 카드. 본문(`.d-body`)은 **한 열 전체 폭**. 예약 카드에서 찜 버튼은 뺐다(상단 막대에 있음).
- **주간 날씨 통일(소유자)**: 페이지 칸(`conditions/card.js`)과 날짜별 팝업(`openWeatherModal`)이 같은 날짜 카드(`.fc-strip`/`.fc-day`)·같은 기호(☀️⛅☁️🌧️❄️⛈️🌫️)·사이트 토큰(초록 강조)을 쓴다. 보라색 하드코딩 제거. 팝업의 날짜 칸·하루 요약(최고·최저·강수확률·하늘)은 **페이지와 같은 기상청 값**을 먼저 쓰고(같은 날 숫자가 다르던 문제), 시간별 그래프만 Open-Meteo 모델(‘참고용’ 표기). 고른 날짜는 가운데로 스크롤. 날짜 카드는 넓은 화면에서 줄을 채운다.
- **모듈 카드 제목 아이콘**: ‘주간 날씨’·‘여행 참고 정보’ 제목에도 다른 섹션과 같은 선 아이콘.
- **이용 정보 줄**: 값 칸(`.use-val`)이 있는 줄은 (i)가 같은 줄 끝에 남고, 값 칸이 없는 글 줄(응급실·물때 등)은 글처럼 줄바꿈해 화면을 넓히지 않는다.
- **주변시설 지도 썸네일**: 다음 지도 이미지에 위경도를 그대로 넘겨 전부 바다(하늘색)로 나오던 것을 WCONGNAMUL 좌표 변환(`wcong`)으로 고쳤다.
- **요금 표기 통일**: 카드·목록·비교의 1박 요금은 `feeLabel`로 `4만~5만원`, 어림값은 `2만~2.5만원대`.

- **모바일 목록**: 사진이 카드 높이만큼 세로로 길게 늘어나던 것을 92px 정사각 사진 + 옆 이름, 나머지 정보는 아래 전체 폭으로. 히어로·목록 검색 칸의 값 글자가 아래로 잘리던 것 수정.

## 조건 검색 — 히어로 ‘조건’ 칸 + 조건 시트 (2026-10-19, Claude · 소유자 요청)

- 히어로 검색은 `권역 → 어디로 → 언제 → 조건 → 찾기`. ‘조건’ 칸을 누르면 조건 시트가 열리고, 아래 줄에 예시 조건 칩(반려견 동반 · 1,100W 이상 전기 · 사이트 8m 이상 · 글램핑·카라반 · 당일 캠크닉 · 장작 불멍)을 바로 켤 수 있다.
- **조건 시트**: 지역(17개 시도, 여러 곳) · 주변(시·군 이름 + 10/20/30km, 그 시·군 캠핑장 좌표의 가운데 기준) · 상품·이용(글램핑·카라반·오토·일반·숙박동·캠핑카·차박·당일 캠크닉 — 하나라도) · 반려견 · 전기(전기 있음/600W+/1,100W+) · 사이트 크기(긴 변 6/8/10m+) · 장작 가능 · 텐트 옆 주차 · 1박 요금대. 각 선택지 옆 숫자는 **다른 조건과 겹치는 곳 수**(0이면 비활성), 아래 버튼은 `N곳 보기`.
- **판정은 세 갈래(소유자 2026-10-19 “데이터가 없어 걸러지는 건 안 좋다”)**: 근거로 맞음(✓ 초록) · 법정 기준으로 맞음(점선, 전기 있음 + W 미공지 → 관광진흥법 사이트당 600W로 보아 ‘600W 이상’에 포함) · **정보 없음은 빼지 않고 ‘확인 필요’(점선 회색)로 결과 아래쪽에 남긴다**. 근거로 안 맞는 곳(반려견 불가, 전기 없음, 등록 규격이 더 작음 등)만 뺀다. 지역·반경은 위치 사실이라 바로 거른다.
- 시트 숫자는 `근거로 맞는 곳 +정보 없는 곳`, 버튼은 `N곳 보기 (확인 n)`. ‘확인된 곳만 보기’(시트·목록 칩, 주소 `strict=1`)를 켜면 정보 없는 곳을 뺀다. 목록 행에는 켜진 조건마다 `✓ 반려견` / `전기 600W+ · 법정 기준 600W` / `사이트 8m+ · 확인 필요` 칩을 보이고, 정렬은 근거 → 법정 기준 → 확인 필요 순.
- 상품은 등록·운영자 근거 타입만 근거로 친다(후기 언급 `m` 제외). 사이트 크기는 고캠핑 규격 등록값.
- 결과는 `#/list?sido=경기,인천&kind=GLAMPING,CARAVAN&size=8&pet=1&w=1100&near=파주&r=20&fee=3to5&d=…`. 목록 위에 켜진 조건 칩(× 해제)과 ‘조건’ 버튼(시트 다시 열기). 행에는 ‘사이트 최대 가로×세로m’를 사이트 타입 줄에 함께 보인다.

## 근거 등급 점에 `r`(법정 기준 참고) 추가 (2026-10-19)

- `v` 원문 대조(채운 점) · `c` 공식 등록·운영자 공개(반 채운 점) · `m` 소개·후기 언급(빈 점) · **`r` 법정 기준 참고(점선 빈 점)** — 업장이 공지하지 않아 법령·고시 기본값을 보인 경우. 값 문구는 “업장 미공지 · 법정 기준 …”으로 시작한다. 배지·내 세팅 판정에는 쓰지 않는다.

## 예약 화면 사이트 표 + 빈자리 관측 표시 (2026-10-19, Claude)

- **상세 ‘사이트 규격 및 1박 요금’**: 예약 엔진(땡큐캠핑)에 업장이 등록한 사이트가 있으면 그 표를 먼저 쓴다(`bookingSitesHtml`). 열: 사이트(이름 + 타입·주차·반려동물 보조줄) / 규격·바닥 / 수 / 1박 요금. 같은 조건 사이트는 `A1 ~ A12`처럼 한 줄로 묶는다. 머리에 `업장 등록 · 10/24(토) 1박 기준` + (i), 아래에 ‘날짜별 예약 화면 열기’ 링크. 요금은 날짜마다 달라질 수 있다고 적는다.
- **빈자리 관측(원천 승인 후에만)**: `explore/data/vacancy.json`이 있고 만료 전일 때만 보인다. 목록 날짜 판단 `빈자리 n/전체`(초록, 1순위)·`만석(관측)`(회색, 빼지 않고 뒤로), 버튼 `빈자리 예약하기`/`예약 화면 보기`. 상세 예약 카드 ‘주말 빈자리 관측’ — 날짜별 `빈자리 n/전체`, `MM/DD HH:mm 확인 · 예약처에서 최종 확인`. 확인 시각 없이 ‘예약 가능’으로 쓰지 않는다.

#### Studio 01 보정 — 320px·상세 데이터 표현 (2026-10-16)

#### Studio 01 입력·상태 컴포넌트 규칙 (2026-10-17)

## v4.4 “Poster Explorer” 운영 적용 (2026-10-18)

1. **실제 주소로 승격한다.** `/explore/`는 `design/renewal/`의 A 포스터 화면을 발행하며, `/`은 그 주소로 바로 연결한다. `/renewal/`은 같은 소스를 확인하는 보조 주소일 뿐 별도 가짜 카탈로그가 아니다.
2. **첫 화면 순서.** 투명 헤더 `찾기·지도·비교` → 실제 한국 캠핑장 사진 히어로 → `이번 주말, 빈자리부터.`와 전국/공식 오픈 수 → 검색 필드 → 빠른 조건/요금 → 곧 오픈 → 후기 신호 좋은 곳 → 테마 사진 레일 → 사진이 있는 전국 결과(320px 2열·넓은 폭 3~5열)를 쓴다.
3. **실데이터만 채운다.** 카드마다 허용된 공식 사진 최대 5장, `01 주차 / 02 전기 / 03 장작`, 근거가 있는 1박 요금대만 표기한다. 상세·비교·지도는 같은 카탈로그/프로필과 원천 팝오버를 공유한다. 날짜·실시간 빈자리·결제 가격을 갖지 않은 데이터는 만들거나 예약 가능으로 표현하지 않는다.
4. **320px·PWA.** `overflow-x: clip`은 문서 전체에만 적용하고, 지역·요금·사진·테마 레일에서만 의도된 가로 스와이프를 허용한다. 헤더는 `safe-area-inset-top`, 하단 탭·상세 예약 행동은 `safe-area-inset-bottom`을 사용한다.
5. **배포 계약.** 새 카탈로그가 발행될 때 `scripts/build-renewal-data.mjs`가 공식 사진 색인(최대 5장)을 다시 만들고, Pages 빌드는 화면 파일과 함께 복사한다. `media` 브랜치 전수 검증에 실패하면 배포를 중단한다.

## v4.5 전체 화면 통일·데이터 밀도 보정 (2026-10-18)

1. **한 주소·한 규칙.** 테마·예약 오픈·이용 가이드·내 캠핑 보조 주소는 독립 템플릿을 두지 않고 `/explore/`의 같은 헤더·여백·카드·PWA 안전영역을 쓰는 해시 화면으로 연결한다. 이 규칙은 `scripts/publish-explorer-pages.mjs`의 정적 진입점에도 적용한다.

3. **미디어 경계.** 고캠핑 공식 사진만 자체 갤러리·목록 캐러셀에 보관한다. 블로그·카페·SNS·외부 플랫폼 콘텐츠는 제목·게시일·원문 링크 또는 허용된 임베드로만 연결하며, 원본/외부 썸네일을 서비스 자산으로 복제하지 않는다.

- **가로폭 전체.** 헤더·본문·보조 페이지의 최대 폭(1240/1280px)을 없애고 좌우 여백 `clamp(16px, 3vw, 48px)`만 둔다. 히어로·상세 사진은 가장자리까지(라운드 없음).

## v4.3 운영 화면 적용(2026-10-18)

시안의 원칙을 `/`와 `/explore/` 운영 화면에 적용한다. 시안처럼 보이는 정적 값으로 바꾸지 않으며, 이미 발행된 캠핑장·프로필 데이터 계약을 그대로 쓴다.

1. **탐색의 첫 선택은 찾기·지도·비교.** 데스크톱 공통 헤더는 세 기능을 먼저 둔다. 테마는 홈의 실제 데이터 가로 레일과 `explore/themes/`의 전체 목록에 둔다. 홈 히어로 아래에는 키워드·테마·지도 3칸만 짧게 설명한다.
2. **히어로와 헤더는 한 장면.** 처음에는 헤더를 히어로 사진에 겹치고, 스크롤한 뒤에만 블러 유리 배경과 경계를 적용한다. 히어로 카피는 두 줄 이내로 제한한다.
3. **실제 데이터의 보이는 순서.** 목록은 공식 사진 캐러셀(최대 5장), 이름, `01/02/03` 조건 행, 근거 있는 요금대, 주변 생활 인프라·후기 요약 순서다. 상세는 예약 CTA → 규격·요금 → 현장 조건 → 후기/영상/사진 → 시설·주변·기본정보 순서다. 미확인 값은 회색 `확인 필요` 텍스트만 쓰고 배지로 강조하지 않는다.
4. **안전영역.** `viewport-fit=cover`와 `env(safe-area-inset-*)`를 사용한다. 상단 헤더/상세의 목록 버튼은 상단 인디케이터 아래에, 모바일 하단 탭/상세 예약 CTA는 홈 인디케이터 위에 놓인다. 모든 페이지는 `overflow-x: clip`; 칩·사진 레일만 숨겨진 스크롤바의 가로 스와이프를 허용한다.
5. **텍스트.** 제목·스펙은 `word-break: normal`, 짧은 라벨은 한 줄, 문장형 설명은 필요한 경우만 1~2줄과 충분한 행간을 쓴다. 근거·출처·판정 방식은 작은 `i`에 접는다.

### PWA·공식 사진 배포 보정 (2026-10-18)

- iPhone PWA는 `viewport-fit=cover`와 `black-translucent` 상태 막대를 쓴다. 사진은 상단 상태 표시 영역까지 이어지되, 헤더·상세 닫기·고정 CTA·하단 탭은 각각 `safe-area-inset-*`만큼 안쪽에서 시작한다. Safari 일반 탭과 PWA 모두에서 문서 전체의 가로 스크롤은 만들지 않는다.
- `/media/`는 `media` 브랜치의 허용된 고캠핑 공식 사진 파생본이다. Pages 배포는 탐색 데이터의 모든 `camps/*-t.webp`와 카드·상세가 쓰는 대응 `*-l.webp`를 전수 대조한다. 하나라도 없으면 사진 없는 화면을 배포하지 않고 빌드를 실패시킨다.

## 조사에서 채택한 원칙

여행 예약 화면은 영감용 사진보다 먼저 **여행 조건과 확정 가능성**을 이해시켜야 한다. 에어비앤비의 사례는 하나의 핵심 흐름, 읽기 쉬운 문장 중심 정보 계층, 저장·예약 같은 명확한 행동을 강조한다. Booking.com의 개발 문서는 위치·날짜·인원과 필터를 분리해 실시간 재고·가격을 조회하는 검색 구조를 보여 준다. Google의 반응형 가이드는 화면 폭이 바뀔 때 단순 축소 대신 탐색·필터 컨테이너의 형태를 바꾸도록 권한다.

캠핑 AR·예약 UI 레퍼런스는 몰입감 있는 실제 사진, 부드러운 큰 모서리, 작은 정보 배지, 사진과 일정의 분리된 계층을 보여 준다. 클로드 시안 v2는 그중에서도 **예약 오픈을 첫 번째 콘텐츠로 두고, 검색을 한 장의 큰 히어로 카드 안에 넣으며, 모바일에서 가로 카드와 하단 탐색을 쓰는 구조**가 서비스 목적에 잘 맞았다. 현재 공개 화면은 이 시안의 메뉴 순서, 큰 사진 히어로, 우측 통계 배지, 히어로 안의 탭형 검색, 가로 예약 카드, 사진 카드, 모바일 하단 탐색을 기준 레이아웃으로 구현한다. 시안의 콘셉트 이미지와 예시 캠핑장·가격은 사용하지 않는다. 대신 공식 사진의 원문, 확인일, 예약의 확정 경계를 같은 화면에서 보여 준다.

그래서 모여라 캠핑은 다음 순서를 고정한다.

1. 첫 화면에서 `캠핑장/예약 오픈`을 고르고 지역·날짜·인원을 입력한다.
2. 검색 바로 다음에 검증 상태와 확인일이 있는 예약 오픈 카드를 둔다.
3. 실제 캠핑장 카드는 사진·형태·규격·정원·공식 예약 안내만 짧게 보여 준다.
4. 상세에서 상품별 재고·요금·정책을 보여 주고, 날씨·경로·주변 여행은 보조 판단 정보로 분리한다.
5. 사진·가격·재고가 없는 기준 시설 레코드는 사진 카드로 꾸미지 않고, 데이터 수집 현황과 검증 상태에서만 보여 준다.

참고: [Airbnb UX 사례](https://design.google/library/airbnb-invites-you-in), [Booking.com 검색 사용 사례](https://developers.booking.com/demand/docs/accommodations/search-examples), [Google의 반응형 패턴 가이드](https://design.google/library/introducing-resizer), [Camping AR App](https://dribbble.com/shots/11607072-Camping-AR-App), [Camping App Exploration](https://dribbble.com/shots/27205497-Camping-App-Exploration), [Camping App Design](https://dribbble.com/shots/10165691-Camping-App-Design), [Ski camps booking](https://dribbble.com/shots/22874895-Snowboard-Ski-camps-booking-web-app), [Camping reservation UI](https://dribbble.com/shots/7140824-Camping-reservation-ui).

## 세로 스크롤 소유권 (2026-10-14)

- 일반 화면은 문서(`html`/`body`)만 세로 스크롤한다.
- 탐색 상세는 열리는 순간 문서 루트를 잠그고, `.sheet-panel` 하나만 세로 스크롤한다. 따라서 배경 목록과 상세 내용이 동시에 움직이거나, 두 개의 세로 스크롤바가 나타나지 않는다.
- 수평 칩·사진 레일은 좁은 화면에서의 의도된 가로 탐색이며, 세로 스크롤바를 추가하지 않는다. 새 `overflow-y` 컨테이너는 모달·상세처럼 불가피한 경우에만 만들고, 그때는 배경 문서 잠금까지 같은 변경에서 검증한다.
