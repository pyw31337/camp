- **조치**: ① `SOURCES`에 `blog_mention`·`cafe_mention`·`kin` 등록. ② 누적 캐시를 `collected-data` 브랜치에 수집 직후 저장·복원(`docs/COLLECTED_DATA.md`). ③ `publish-incremental.sh`: 수집 직후 최신 main 위에 덧붙이고(`merge-collected.mjs`) 파생 재계산 → `coverage-guard.mjs` → 바로 커밋(데이터 동기화의 웹 언급 직후, 운영자 홈페이지 읽기 직후). ④ 최종 전체 빌드에도 회귀 검사. ⑤ 업로드 아티팩트는 항상(`if: always()`).
- **OCR 단계 분리**(`crawl-operator-sites.mjs`): 크롤 중에는 안내 이미지 주소만 모으고, 크롤이 끝난 뒤 동시 2개·전체 `--ocr-minutes`(60)·캠핑장당 120초로 따로 읽는다. 이전 방식은 동시 크롤 10개와 CPU를 다퉈 사이트 제한 시간에 잘려 결과가 거의 0이었다.
- **참고**: 최신 main에서 파생 빌더만 다시 돌려도 입실 +10·전기 W +48·사이트 타입 +63이 오른다(발행 데이터가 최신 스크립트보다 늦음). 첫 증분 발행에서 함께 반영된다.
