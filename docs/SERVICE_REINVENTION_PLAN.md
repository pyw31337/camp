# 모여라캠핑 재정의 계획 — 최근 관측 빈자리와 캠핑 적합성

> 상태: 제안 확정 전 설계 · 2026-10-15 KST<br>
> 이 문서는 `PROJECT_PLAN.md`의 제품 목표를 구체화한다. 구현 우선순위, DB 마이그레이션, 외부 데이터 수집은 이 문서의 원천·표시 규칙을 승인한 뒤에만 진행한다.

## 1. 한 줄 정의와 하지 않을 일

**모여라캠핑은 내 가족·차량·장비에 맞고 최근에도 빈자리가 관측된 캠핑장을 비교해 주는 캠핑 준비·결정 서비스다.**

예약 플랫폼을 복제하거나, 즉시 확정 재고를 보장하거나, 후기·사진을 대량으로 재게시하는 서비스가 아니다. 사용자는 모여라캠핑에서 후보를 줄이고 현장 실패를 예방한 뒤, 공식 예약처에서 예약·대기 신청을 끝낸다.

| 기존 탐색의 불편 | 모여라캠핑의 답 |
| --- | --- |
| 예약처와 업장 공지마다 필요한 조건이 흩어져 있음 | 같은 사전과 단위로 정규화한 `현장 조건표` |
| 빈자리는 휘발되지만 며칠 남는 곳을 찾기 어려움 | 날짜·인원 조건별 `최근 관측됨`과 관측 이력 |
| “주차 가능”, “전기 있음”이 실제 준비에 부족함 | 사이트 옆/외부/하차 후 이동, 최대 W, 바닥, 구역별 규격까지 구분 |
| 아이·장비·차량에 맞는지 직접 판단해야 함 | 내 캠핑 프로필 기준 `가능 / 조건부 / 확인 필요 / 맞지 않음` |

## 2. 진실성 계약: 실시간 재고와 관측을 분리한다

다음 상태는 이름·저장소·화면 문구를 절대 섞지 않는다.

| 상태 | 의미 | 화면 문구 | 기본 노출 |
| --- | --- | --- |
| `LIVE_AVAILABLE` | 계약/API가 시설·상품·날짜·인원·재고를 반환 | 현재 예약 가능 | 짧은 TTL 안에서만 |
| `OBSERVED_AVAILABLE` | 허용된 원천이 그 조건에 예약 가능한 상품을 보여 준 것을 관측 | `10/15 02:40에 빈자리 관측` | 최근 관측 필터의 기본값 |
| `OBSERVED_UNAVAILABLE` | 같은 조건의 허용된 원천에서 다음 관측 때 빈자리를 보지 못함 | `10/16 03:10에는 미관측` | 기본 목록에서 숨김, 이력에는 유지 |
| `OFFICIAL_APPLICATION_OPEN` | 공식 원천이 접수 상태만 제공 | 공식 접수 중 · 잔여 수 미제공 | 날짜 조건 일치 때 |
| `UNKNOWN` / `OBSERVATION_FAILED` | 원천을 읽지 못했거나 허용된 관측 경로가 없음 | 확인 필요 | 빈자리 후보로 쓰지 않음 |

`OBSERVED_UNAVAILABLE`은 매진 확정이 아니다. 취소분·날짜/인원 차이·원천 화면 변경 때문에 다시 보일 수 있다. 따라서 이전 기록을 삭제하지 않고, **더 최신의 같은 조건 관측만** 기본 카드 상태를 갱신한다.

### 최근 관측 기본 규칙

- 기본 탐색: 마지막 `OBSERVED_AVAILABLE`이 36시간 이내이고, 이후 같은 상품·날짜·인원 조건의 `OBSERVED_UNAVAILABLE`이 없는 후보.
- 사용자는 24시간 / 48시간 / 전체 이력을 바꿔 볼 수 있다.
- 카드에는 `관측 시각`, `관측 기준(날짜·숙박일수·인원)`, `예약처`, `원문 열기`를 항상 함께 둔다.
- “몇 자리 남음”은 원천이 명시적으로 수량을 제공한 `LIVE_AVAILABLE` 외에는 표시하지 않는다.

## 3. 제품 경험

### 3.1 첫 화면: 이번 주 어디로 갈까

첫 질문은 “어느 캠핑장이 좋아?”가 아니라 아래 조건이다.

1. 입실·퇴실일, 성인·아이·차량 수
2. 내 장비: 텐트 폭×깊이, 타프/쉘터, 캐노피, 필요한 전력
3. 필수 조건: 최근 빈자리 관측, 사이트 옆 주차, 장작/숯, 반려견, 아이 물놀이 등
4. 선호 조건: 계곡·산책·수영장·에어바운스·체험·조용함·대여 장비

결과 상단에는 `이번 주 1박 · 최근 24시간 내 빈자리 관측 · 23곳`처럼 조건을 다시 쓰고, “빈자리 관측 기준”을 바로 열어 볼 수 있게 한다.

### 3.2 목록 카드: 예약 가능보다 준비 가능

카드의 정보 우선순위는 사진·후기보다 아래 순서다.

1. 마지막 빈자리 관측 시각과 예약처
2. 내 조건 판정: 가능 / 조건부 / 확인 필요
3. 주차 방식, 전력 W, 사이트 바닥·규격
4. 아이 시설·물놀이·체험, 화장실·샤워실, 대여 핵심 정보
5. 사진과 후기 링크는 분위기 판단을 위한 보조 정보

### 3.3 상세: “현장에서 막히는 것”을 먼저

상세 상단에는 `예약 전 중요 정보`와 `내 캠핑 세팅 판정`을 둔다. 이후 구역/상품별 표에서 다음을 보여 준다.

- 사이트명·구역명, 면수, 가로×세로, 바닥, 차량·주차 동선
- 전기 제공/최대 W/콘센트 위치, 텐트·타프·캐노피 설치 수량·규격
- 숯·장작·화로·우천 시 규정
- 공용/개별 화장실·샤워실·개수대 수, 온수 여부
- 오토·글램핑·카라반 등 유형별 총 수와 대여 품목·가격·예약 필요 여부
- 수영장·에어바운스·놀이터·계곡·천·산책길·프로그램의 운영 기간과 비용

모든 값은 `확인됨`, `조건부`, `확인 필요`를 구분하고 원문 링크·확인일을 가진다.

## 4. 정규화 데이터 모델

기존 `campground → campground_zone → product → inventory_unit`은 유지한다. 다음은 별도 추가 마이그레이션(`db/008_…`)으로 도입하며, 기존 `availability_snapshot`의 실시간 의미를 바꾸지 않는다.

| 모델 | 핵심 열 | 용도 |
| --- | --- | --- |
| `condition_fact` | 범위(캠핑장/구역/상품/사이트), `field_code`, 구조화 값, 검증 상태, 유효기간 | 주차·전력·바닥·불멍·캐노피 같은 사실 |
| `rental_offer` | 상품/시설, 품목, 가격·보증금, 재고·사전예약, 유효기간 | 대여 텐트·화로·전기장판 등 |
| `facility_feature` | 유형, 범위, 수량, 운영 기간, 비용, 연령/안전 제약 | 수영장·에어바운스·체험·계곡·산책로 |
| `availability_observation_run` | 허용된 커넥터, 실행 시각, 요청 조건 해시, 성공/실패, 원천 증빙 | 관측 작업의 감사·재시도 |
| `availability_observation` | 상품/사이트, 날짜·인원·차량, 관측 상태, 수량(있을 때만), 원문·시각 | 일 단위 최근 빈자리와 이력 |

`condition_fact.field_code`의 첫 사전은 다음으로 고정한다.

```text
PARKING_MODE            SITE_ADJACENT | SHARED_NEARBY | DROP_OFF_EXTERNAL | CART_REQUIRED
POWER_MAX_W             정수 W, 적용 범위와 추가 요금 분리
SITE_SURFACE            DECK | GRAVEL | GRASS | SOIL | MIXED
FIREWOOD_ALLOWED        ALLOWED | PROHIBITED | DESIGNATED_ONLY | UNKNOWN
CHARCOAL_ALLOWED        ALLOWED | PROHIBITED | DESIGNATED_ONLY | UNKNOWN
SHELTER_SETUP_RULE      텐트/타프/쉘터/캐노피 수량·최대 규격·금지 유형
SANITARY_TYPE_COUNT     화장실·샤워·개수대의 공용/개별·수량·온수
```

`condition_fact`는 값만 저장하지 않는다. `source_url`, `observed_at`, `source_published_at`, `verification_status`, `reviewer`, `supersedes_fact_id`를 보존한다. 값 충돌은 최신값으로 덮지 않고 함께 남겨 검토 큐로 보낸다.

## 5. 원천과 수집 정책

플랫폼을 피해서 자동 수집 시간을 숨기거나 탐지를 회피하는 방식은 사용하지 않는다. 커넥터는 아래 중 하나여야 한다.

1. 공식 API 또는 서면 제휴 데이터
2. 캠핑장 운영자가 직접 인증한 운영자 포털 입력
3. 재배포·자동 조회가 허용된 공공/공식 데이터
4. 사람이 원문 URL과 화면 확인 시각을 첨부해 검수한 입력

허용된 일 1회 관측은 평일 업무 시간(08:00~18:00 KST)을 피한 야간·이른 아침 배치 창에서 실행할 수 있다. 이는 탐지 회피가 아니라 약정된 호출량·rate limit·운영자 서비스 품질을 지키기 위한 운영 정책이다. 공급자별 호출 주기, 최대 요청량, 실패 중단 기준은 커넥터 계약에 명시한다.

운영자 인증은 가장 중요한 수집 경로다. 캠핑장에는 “무료 공식 조건표”를 제공하고, 전력 W·주차·구역별 크기·대여료·아이 시설을 직접 갱신하게 한다. 대가로 순위 구매나 허위 “추천”은 제공하지 않는다.

## 6. 공개 데이터와 개인화의 경계

- 캠핑장 조건·관측 이력은 검증 상태와 함께 공개 가능한 데이터다.
- 사용자의 차량·아이 나이·장비 크기·저장 목록은 로그인 전 브라우저 로컬에만 저장한다.
- 적합성 판정은 우선 브라우저에서 계산한다. 서버에는 개인 조건을 저장하지 않는다.
- 출발지·경로는 사용자가 길찾기를 누른 순간에만 사용하고 장기 보관하지 않는다.

## 7. 단계별 실행

### 단계 A — 계약과 파일럿 (2주)

- 이 문서의 상태명·필드 사전·표시 문구를 확정한다.
- 운영자 20~30곳 또는 허용된 공식 공급자 1곳으로 파일럿 원천을 확보한다.
- 사이트/구역별 조건표 입력 템플릿과 검수 큐를 만든다.
- **완료 기준:** 전력·주차·규격·바닥·불멍·위생·대여·아이시설을 각각 원문과 함께 입력할 수 있다.

### 단계 B — 최근 관측 탐색 (2~3주)

- `availability_observation_*` 마이그레이션과 허용된 단일 커넥터를 구현한다.
- 날짜·인원별 관측 이력과 36시간 기본 필터를 정적 읽기 모델로 발행한다.
- **완료 기준:** 임의의 파일럿 날짜에서 관측 시각·후속 미관측·원문 링크를 혼동 없이 카드와 상세에 보인다.

### 단계 C — 내 캠핑 프로필과 적합성 (2주)

- 차량·텐트·타프/캐노피·전력·아이 조건을 로컬 프로필로 저장한다.
- 조건별 `가능 / 조건부 / 확인 필요 / 맞지 않음`의 설명 가능한 판정기를 구현한다.
- **완료 기준:** 판정마다 사용한 사이트/조건 사실과 불확실성을 사용자가 확인할 수 있다.

### 단계 D — 운영자 확장과 품질 관리

- 운영자 인증 링크, 만료 알림, 정정 제보, 변경 이력을 만든다.
- 최신성·근거 완전성·정정 처리 시간을 운영 지표로 관리한다.

## 8. 성공 지표와 중단 기준

| 지표 | 초기 목표 |
| --- | --- |
| 파일럿 시설의 핵심 조건 근거 완전성 | 90% 이상 |
| 최근 36시간 내 관측 후보의 원문 링크·시각 보유율 | 100% |
| 카드에서 공식 예약처로 이동하기 전 조건 비교 완료율 | 사용자 조사로 측정 |
| 운영자 정정 요청 처리 시간 | 3영업일 이내 |
| “확인 필요”를 “가능/불가”로 잘못 표시한 건 | 0건 |

신뢰 가능한 원천이나 운영자 참여 없이 전국 단위 빈자리 수집을 확대하지 않는다. 파일럿에서 근거 완전성·갱신 가능성이 나오지 않으면, 빈자리 기능은 공식 링크 허브로 후퇴하고 조건 데이터 품질에 집중한다.

## 9. 클로드·코덱스 공용 작업 규칙

두 작업자는 이 문서와 `AGENT_HANDOFF.md`를 공용 결정 기록으로 쓴다.

1. 제품 상태명·필드 사전·출처 정책 변경은 이 문서의 결정 로그를 먼저 갱신한다.
2. 한 작업 단위는 `기획`, `DB/파이프라인`, `탐색 UI`, `운영자 입력` 중 하나만 맡아 파일 충돌을 줄인다.
3. 다른 작업자가 수정 중인 파일은 덮어쓰지 않고, 인수인계에 파일·커밋·미해결 결정을 남긴다.
4. 실제 플랫폼 데이터 수집·배포 전에 원천 허용 범위와 사용자 표기 문구를 함께 검토한다.
