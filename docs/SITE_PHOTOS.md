# 상품(사이트 유형·구역)별 사진 수집 (2026-11-11 소유자 t55)

> “업장별 사진뿐 아니라, 이제 업장별 상품들의 사진도 충분히 수집되어야 하는 단계야. 수집범위를 최대로 넓혀서 모든 수집 가능한 사진들을 모두 수집해줘.”

카드 미니 레일·상세 요금 칸의 **사이트 유형 타일(오토·데크·글램핑·카라반·방갈로/펜션 …)에 그 유형이 실제로 보이는 사진**을 붙이기 위한 파이프라인이다.
캠핑장 대표 사진(`camps/`, `sync-images.mjs`)·카드 사진(`cards/`, `sync-card-photos.mjs`)과 따로 `sites/`에 둔다.

## 판정 규칙 (`lib/site-photo-classify.mjs`, RULE_VERSION 3)

- CLIP 두 모델(`Xenova/clip-vit-base-patch32`, `Xenova/clip-vit-large-patch14`, 무료·로컬 CPU) 제로샷. 사이트 부류 12개(글램핑·글램핑 실내·카라반·카라반 실내·방갈로/캐빈·펜션 건물·객실·데크·파쇄석·잔디·캠핑카·차박)와 ‘상품 아님’ 부류 13개(풍경·조감도·화장실/관리동/간판·매점·놀이/수영장·운동 시설·음식·인물·동물·글/지도/요금표·야경 조명·주차장·마을/옥상).
- 작은 모델이 상품 사진이 아니라고 뚜렷하게 보면(사이트 부류 합 < 0.25) 큰 모델은 건너뛴다(결과가 같아 시간만 줄임).
- **쓰는 조건**: 두 모델이 같은 갈래(글램핑·카라반·객실/방갈로·노지 사이트)로 보고, ‘상품 아님’ 확률이 0.25 미만, 한쪽 ≥ 0.5·다른 쪽 ≥ 0.3.
  건물(객실·방갈로)은 두 모델 모두 ≥ 0.55이고 한쪽이 ‘방갈로/캐빈’이며 ‘상품 아님’ < 0.15, 실내는 두 모델 모두 ≥ 0.6, 데크는 두 모델 모두 ≥ 0.45, 운영자 사진은 두 모델 모두 ≥ 0.5·‘상품 아님’ < 0.2.
  강한 글 단서(객실 이름·alt)가 유형을 말하면 한쪽 모델만 뚜렷해도 쓰고, 그림 갈래와 다르면 버린다. 글이 배치도·요금·매점·화장실 등을 말하면 버린다.
- 캠핑장에 실제로 있는 유형(`c.st`·`site_types`)에만 붙인다. 크기 400×260 미만·배너 비율(2.6:1↑)·세로 2:1↑·서류/배치도 파일은 버린다.
- 한 캠핑장 안에서 같은 사진(dHash ≤ 6)은 한 유형에만, 유형당 6장. 세 곳 넘는 캠핑장에 똑같이 붙은 사진(체인 공통·‘사진 준비중’)은 뺀다.
- 표본 대조: 1차 77장 정밀도 약 80% → 문턱·부류 보강 → 60장 약 93% → 운영자·건물 문턱 → 전체 실행 표본(아래 기록).

## 화면(미리보기 t54-cards만)

`media/sites/index.json`을 첫 화면을 막지 않게 뒤에 받고(`refreshRailPhotos`), 타일 유형 → 같은 갈래 유형 순으로 사진을 고른다(노지: 오토↔일반↔타프존↔반려견…, 객실: 펜션↔방갈로). 같은 레일에서 같은 사진은 한 번만. 사진이 없거나 깨지면 아이콘. 타일을 누르면 모달에 그 유형 사진 줄(최대 6장)과 “사진: 출처”가 나온다.

## 지우지 않기

판정 캐시는 쌓기만 한다(RULE_VERSION을 올릴 때만 다시 판정). `sites/` 파일은 선정에서 빠져도 지우지 않는다. 기존 `site_products[].photos`(#720, 캠핑장 사진 풀을 유형 구분 없이 붙인 값)는 그대로 두고, 화면이 유형별로 확인된 사진을 쓰려면 이 색인을 먼저 본다.

## 공식 채널(홈페이지·블로그·카페·SNS) (2026-11-11 소유자 t60)

많은 업장이 자체 홈페이지 대신 공식 네이버 블로그·카페·인스타그램을 고캠핑 홈페이지 칸에 올려 둔다. `lib/official-channels.mjs` 가 카탈로그 URL(홈페이지·예약 경로 등)만 모으고, 후기·요금 근거 글·VR 업체 글은 제외한다.

소유 확인: (1) 고캠핑·카탈로그 홈페이지로 업장이 직접 등록한 채널 뿌리 주소, 또는 (2) 채널 이름·소개에 시설명·전화·주소가 맞음. 같은 채널 아이디를 서로 다른 캠핑장 4곳 이상이 쓰면 공유 채널로 빼고, 제목에 ‘후기’가 있으면 뺀다.

사진 수집은 위 원천 표와 같다. 상세 화면의 플랫폼 배지·업체 정보 목록은 미리보기에서 먼저 보여 주고, 실제 사이트 반영은 소유자 확인 뒤에 한다.
