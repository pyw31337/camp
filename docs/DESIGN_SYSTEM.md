# 모여라 캠핑 디자인 시스템

> 최종 갱신: 2026-10-12 KST<br>
> 적용 범위: 검색·결과·상세·여행 계획 화면<br>
> 현재 기준: **디자인 시안 v1** (`design/mockup/index.html`, 승인 대기). 승인되면 아래 ‘시각 토큰(v0)’을 v1 토큰으로 교체한다.

## 조사에서 채택한 원칙

여행 예약 화면은 영감용 사진보다 먼저 **여행 조건과 확정 가능성**을 이해시켜야 한다. 에어비앤비의 사례는 하나의 핵심 흐름, 읽기 쉬운 문장 중심 정보 계층, 저장·예약 같은 명확한 행동을 강조한다. Booking.com의 개발 문서는 위치·날짜·인원과 필터를 분리해 실시간 재고·가격을 조회하는 검색 구조를 보여 준다. Google의 반응형 가이드는 화면 폭이 바뀔 때 단순 축소 대신 탐색·필터 컨테이너의 형태를 바꾸도록 권한다.

그래서 모여라 캠핑은 다음 순서를 고정한다.

1. 첫 화면에서 지역·날짜·인원을 입력한다.
2. 결과에서 캠핑 형태와 현장 조건을 좁힌다.
3. 카드에서 예약 상태, 원천, 수집 시각, 가격·정원·규격을 사진과 함께 읽는다.
4. 상세에서 상품별 재고·요금·정책을 보여 주고, 날씨·경로·주변 여행은 보조 판단 정보로 분리한다.

참고: [Airbnb UX 사례](https://design.google/library/airbnb-invites-you-in), [Booking.com 검색 사용 사례](https://developers.booking.com/demand/docs/accommodations/search-examples), [Google의 반응형 패턴 가이드](https://design.google/library/introducing-resizer).

## 디자인 시안 v1 (2026-10-12)

이전 프로토타입은 서비스 설명 위주라 사용자가 무엇을 얻는지 보이지 않았다. v1은 [데이터→UX 조사](./RESEARCH_DATA_TO_UX.md)의 핵심 베네핏 네 가지를 화면 주인공으로 삼는다.

| 화면 | 주인공 | 구성 |
| --- | --- | --- |
| 홈 | 곧 열리는 예약 | 히어로 검색(지역·날짜·인원·**내 장비**), D-day 오픈 카드 가로 스크롤, 베네핏 4개를 실제 UI 조각으로 시연, 신뢰 등급 A~E 설명 |
| 검색 | 내 장비 맞는 자리 | 고정 검색 요약, 필터 칩(장비 적합·상품 유형 7종·예약 방식), 결과 카드(상품 수, 적합 사이트 규격, 예약처·다음 오픈 D-day, 주말 날씨·이동·통행료, 출처 배지), 지도(데스크톱 우측 고정, 모바일 토글) |
| 상세 | 예약 방법 패널 | 우측 고정 패널(예약처·방식·카운트다운·일정 타임라인·알림), 주말 컨디션, 상품 비교표, **사이트 배치 시뮬레이터**(실측 비율로 텐트·타프·차량 배치), 최근 현장, 정보 출처 |
| 오픈 캘린더 | 한 달력 | 관심/전체 전환, 월간 그리드(모바일은 색 막대), 다가오는 일정 목록과 알림 토글, 확인 필요 배지 |

참고한 구조: Airbnb(사진 중심 결과 카드 + 우측 고정 예약 패널 + 지도 분할), Booking.com(조건 요약 바와 필터 칩), Hipcamp(사이트 단위 정보·현장 조건). 차별점은 가격이 아니라 **예약 오픈 시점과 사이트 규격**을 카드의 1순위 정보로 올린 것이다.

### v1 반응형 검수

320·390·1280px, 라이트/다크에서 4개 화면 모두 가로 스크롤 0, 콘솔 오류 0(Playwright, 2026-10-12). 모바일(≤760px)은 상단 메뉴 대신 하단 탭바, 캘린더 이벤트는 색 막대로 축약, 표는 자체 가로 스크롤.

## 이미지 원칙

- 실제 캠핑장 카드: 운영자·공식·계약된 공급자 이미지와 권리·확인일을 함께 표시한다.
- 현재 프로토타입: 서비스 콘셉트 이미지만 사용하며 실제 시설 사진으로 표시하지 않는다.
- 이미지 카드: 16:9 비율, `object-fit: cover`, 고정된 정원·가격 정보와 시각적으로 분리된 메타데이터를 쓴다.
- 접근성: 대표 이미지는 대체텍스트를 제공하고, 장식용 카드는 빈 대체텍스트를 사용한다.

## 반응형 규칙

| 범위 | 레이아웃 |
| --- | --- |
| 961px 이상 | 좌측 필터 + 2열 카드, 한 줄 검색바 |
| 681–960px | 2열 정보 카드, 간결한 검색바, 보조 플로팅 카드 숨김 |
| 361–680px | 검색 조건을 2열 카드로 재배치, 필터는 바텀시트, 결과 카드는 1열 |
| 320–360px | 좌우 여백 16px, 브랜드 배지 축소, 검색 버튼 전체 폭, 표의 상태는 다음 줄로 이동 |

320px 기준으로 페이지의 최소 폭을 보장하고, 고정 폭·긴 버튼·불필요한 강제 줄바꿈을 피한다. 단어가 길어진 표 셀은 줄바꿈을 허용하되 화면 밖으로 넘치지 않게 한다.
